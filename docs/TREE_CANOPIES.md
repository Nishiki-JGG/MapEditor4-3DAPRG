## 既存の全木と木質低木

## 表現と負荷

- 葉塊は不規則な7面の天面が基本。見えにくい下面を追加せず、頂点色の高さ別の明暗・色相差、中心寄りの局所AO、上向きの滑らかなクラスター法線を使用する。紅葉や桜の色は樹種ごとに維持する。
- 葉の隙間をアルファテストの実モデルから影へ反映。隠し影モデル、デカール、追加のライトは使わない。異形の木の従来の点光源だけ維持する。
- 幹・根はウェイト0。枝の途中から先へ重みを補間し、葉塊の中は同じ変位にして塊が裂けるのを抑える。ヤシ・バナナは根元から葉先へ連続ウェイト。GPUの水平変位で、毎フレームのCPU全頂点更新は行わない。
- 既存の風の伝播・接触用空間グリッド・減衰処理を再利用。高い樹冠は1.8mの人物へ接触反応しない。標準寸法の枝下は2.15m以上。低木2種は地面近くの葉を持つ。
- 同種でも配置位置による風位相と既存の回転・拡縮・色差がある。メッシュ自体は種類ごとの決定的な形であり、多数の自動形状バリアントを追加してはいない。
- 既存12対象の合計は4,124 → 3,930三角形。新規12種は合計6,027三角形（全種類を各1本置いた場合）。世界樹は871三角形・1材質だが、樹冠が約23×18mを覆い、透過部分と影のピクセル負荷は通常木より大きい。乱用しない。
- 新規共用画像は1024×512 PNG 1枚、264,536 bytes。sRGB・三線形ミップ・異方性2。RGBA8＋ミップの理論容量は約2.67MiB。既存6画像は変更なし。旧コード生成アトラスの模様と新しい手続き描画だけから作り、外部画像は使用していない。ライセンス・配布条件は変更しない。
- 共有データは32→49資産、ライブラリ `shared-plants/7`、schemaVersion 1を維持。数値の1µm量子化と頂点索引化を使用。`assets.js` は 6,750,794 → 8,182,567 bytes。zlib圧縮の参考値は 1,494,394 → 2,055,175 bytesで、実際の配信圧縮を保証する数値ではない。
- 全対象1材質/種類。既存の種類別インスタンシングに従い、影も同じメッシュ・マスク・変形を使う。新規12種類の主描画・ゴースト用の行列と色のTypedArrayは合計7,529,472 bytes、接触配列は合計1,152,000 bytes増える。これは計測した配列容量で、GPUやアプリ全体の使用メモリではない。

## 検証

- 形状・旧外形維持・25個の対象外共有資産/既存6画像不変・法線/面向き・非退化・UV・固定根幹・葉塊の剛体ウェイト・標準枝下など815項目。
- 実エディターで96種類の一意性、旧84種順序と旧マップ、全24対象の選択・配置・削除・キー回転・拡縮・保存読込・Unity書き出し・CSV丸め誤差を208項目で検査。
- WebGL2の実GPU変換を36可動資産で検査。無風、異なる時刻、最大風＋接触、位置位相、回転/非一様拡縮、固定根元、上限制限を確認。静止比較8µm・参照との差20µm以内というFloat32の数値許容値を使用。
- 本体で全24対象を無風/そよ風/強風、時刻0/2.4秒の同じカメラで撮影。標準と0.6倍で接触、高さ判定、連続接触20秒の上限、離脱6秒後の完全復帰、頂点配列更新がないことを検査。GPU変位を地面の原点高さで投影した参考値は強風で約1.1〜6.6px（通常木17m、エルフ30m、世界樹65mの検査距離）。これはスクリーンへの数値投影で、画素を追跡した測定ではない。
- 隔離Unity 6000.5.9f1 / URP / D3D11で245項目を通過、正常終了。49共有資産、26配置、36資産GPUと追加上限ケース、接触・復帰、旧v2〜v6の取り込み、全24対象の実描画と影、発光属性を確認。GPU比較の最大差は約3.9µm。ゲーム本体へは組み込んでいない。
- 既存12対象は同一カメラ・同じ照明の真上/斜めで前後撮影。追加12種の一覧、単体、人型、混在林、Unity描画をユーザーPC上の隔離Chrome/Unityで目視確認。ブラウザ描画はSwiftShaderであり、スマホ実機性能は未測定。

484本の混在林・2,400回の接触更新で、候補は最大27本。ユーザーPCのChromeで計15.6ms（検査ループと統計収集を含む）、平均約0.0065ms/回。個別計測は中央値0、95百分位約0.1msで時計分解能が粗い。描画速度やスマホ性能の測定値ではない。

最大合成変位の保守的な包絡を水平8方向へ加え、24対象の面反転がないことも検査。葉塊は内部の同一ウェイトで形を保つ。一方で柔軟な葉・細枝の局所辺長比は約0.779〜1.227であり、全メッシュが完全に長さ不変の骨格曲げではない。

## 制限と再生成

- 既存の低い縮尺では枝下も下がる。例えば枝下2.4mの木を0.8倍にすると約1.92m。2.15mの余裕が必要なら0.9倍以上を目安にし、樹種ごとの実際の寸法を確認する。縮小して人物が届く葉は接触する。
- 地面に植える根は原点基準で、凹凸のある地形へ自動的に全根を追従させる方式ではない。急斜面や根際では浮き/埋まりを確認する。配置・地形・水の仕様は変更しない。
- 近景では薄い葉塊、遠景ではアルファの間引きが見える場合がある。ミップと密度で抑えるが、専用LODやスマホ実機の最適化は今回実施していない。
- D3D12では以前の検証終了時クラッシュの原因が未解決。今回は既知のD3D11で確認。Built-inの実シーン描画やゲーム本体統合は未検証。

生成元は `tools/plants/tree-canopies.js`、従来寸法は `tree-legacy.json`。`node tools/plants/bake_trees.cjs` で再生成。旧植物のベイクを使ったときは最後にこのベイクを実行し、樹木を旧版に戻さない。既存6画像と対象外資産の検査を必ず行う。

検査コード: `tests/tree_source.py`、`tree_validation.cjs`、`tree_gpu.cjs`、`tree_review.cjs`、`tree_motion.cjs`、`tree_visual.cjs`、`tree_public.cjs`、`tests/unity/TreeCanopyChecks.cs`。生成・検査の画像やUnityプロジェクトは公開リポジトリへ含めない。

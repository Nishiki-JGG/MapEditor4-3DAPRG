# 画面内の照明（2026-11-04）

従来は中心から40m以内の近い6灯だけを点灯していました。発光キノコが手前に集中すると、画面内に見える松明も点灯枠から外れます。

## 変更

- 固定16枠を、現在のカメラに光が届く光源から選ぶ。
- 画面内の光源を優先し、松明・篝火・壁灯を発光キノコ・水晶より優先する。
- 画面外でも照射範囲が画面に届く光源は候補に残す。40mの打ち切りはカメラが渡らない旧呼出しだけに残す。
- カメラ更新後、0.1秒間隔で候補を選ぶ。既存の優先維持とフェードで切替を緩和する。
- 壁灯の影は近い2灯まで。ほかの選択された壁灯は影なしで点灯する。影なし光源の壁越しの漏れを完全には防がない。
- 灯具ごとの強さ・照射距離、屋外光、保存データ、地形、配置、Unity側の処理は変更しない。
- 炎の火の粉・煙も、画面に映る場合は中心距離だけで消さない。

## 確認

実Chromeで、近くの発光キノコ6個と画面内の松明10本を配置。修正前は松明7本が点灯枠から外れ、修正後は10本とも点灯。40m外の画面内松明、視点変更後の消灯も確認。`node tests/visible-lights-browser.cjs` で再現可能。

既存洞窟1マップの歩行位置・向き3条件でも画面内の炎の光源は点灯し、JS例外・シェーダーエラー・WebGLエラーは0。PC・1100×800・45フレームの簡易比較では、CPU中央値は0.8→1.0ms、GPU中央値は1.05→5.74ms。灯数増によりGPU負荷は増える。短時間のPC測定であり、スマートフォンの性能を保証するものではない。

最大16灯なので、画面内にそれ以上の光源が集中した場合は優先順位で選ぶ。全マップの全光源を常時点灯する変更ではない。

固定サンプルの完成面と保存キーは不変。表示コードのキャッシュと生成元のハッシュ記録だけ更新し、再生成を要求しない。

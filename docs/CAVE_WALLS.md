# 洞窟壁・接続・入口の第三バッチ

床の第二バッチ `01346c5` に続くローカル改善。push・公開は行っていない。

## 選定と見た目

既存壁6種、90度の内角、外角・終端、入口を、真上・斜め・歩行・低視点で実描画して比較した。基本壁 `cliff` の上端には、主岩から独立した薄片が帽子のように浮いて見えた。角は既存 `cliff_joint` と `cliff_slab` / `cliff_talus` で接続できたため、専用品や新しい種類は増やさない。

洞窟の基本壁だけ、上部の小さい独立成分152三角形を描画から除き、連続した主岩の輪郭を元の高さまで伸ばす。元の幅・高さ・原点を維持し、通常配置の描画は602→450三角形。不要になった頂点も描画コピーから除き、法線は縦倍率に合わせて補正する。描画・影・配置プレビュー・フェード表示を同じ形にする。他の5部品と、洞窟以外の基本壁は変更しない。

入口は既存のシダ・苔付き小岩・地這いツタを使う。シダを洞窟パレットから選べるようにし、「入口・天窓など光の入る場所用」という説明を付けた。植物の形、テクスチャ、風・接触パラメータは変更せず、暗い奥へ自動配置する処理も追加しない。

## 衝突・保存とUnity

元の `PROP.geo` と加工済み岩の確定頂点は不変。描画だけのコピーを作り、頂点を毎フレーム書き換えない。通常・行列による加工・直接加工の3経路に対応する。行列加工は同じ描画メッシュを再利用し、直接加工ではその形状ごとにキャッシュする。元形状を破棄した際は描画コピーも破棄する。

旧ID・カタログ105種の順序、保存マップ、元部品SHA、加工岩データ、衝突、通路を保つ。互換性のため、描画と旧衝突形状の細部は完全一致しない。今回の修正は見た目の改善であり、物理形状の更新ではない。

洞窟の該当壁がある場合だけ、任意の `cave_wall_visuals.json` を書き出す。モデルは共有し、配置行列・色倍率・通常/加工済みの指定を添える。既存 `cliff_fits_mesh.json` は衝突を含め変更しない。旧保存形式や必須機能フラグは増やさず、非対応の読込側は任意の見た目補正を無視できる。

Unityの `CaveWallVisualsV1.Apply` は、元部品SHAを確認した通常配置と、既存 `CliffFitsMeshV1.Apply` の適用済み配置へ描画だけを追加する。旧Rendererを無効にして置換し、Colliderには触れない。既存材質・MaterialPropertyBlock・影設定を継承する。通常配置は元オブジェクトの子として移動に追従する。加工済み岩の絶対座標メッシュは従来どおり、配置を変更する場合にエディタから再書出しが必要。

これは隔離プレビューで確認した補助読込器。ゲーム本体のPrefab resolverへ自動接続していない。Unityの岩材質は呼出側が用意するもので、Webの岩の細粒シェーダーまで完全一致させる変更ではない。

## 検証・負荷

- ブラウザ2,369項目：元形状・元部品SHA・保存・加工岩書出しの不変、2,337地点の通行、通常/行列加工/直接加工、再読込、洞窟外の旧描画、配置プレビュー、シダの選択と説明、shaderエラーなし。
- Unity6000.5.9f1/D3D11の隔離プロジェクトで4,085項目：通常壁6種と2加工配置、元ColliderのMesh・有効状態・三角形の保持、描画頂点の一致、配置移動、既存材質・個別材質設定・影、再適用の拒否。今回の24m例で頂点位置差0。
- 同じ検査シーンの描画は17回のまま、描画三角形47,767→47,311。プログラム数72→72。Unityの有効Rendererは8→8、岩材質は1のまま。
- 新しいモデルID・画像・ブラウザ材質・テクスチャ・配置バッファは増やさない。基本壁の描画コピーは約50KiB（既存インスタンス属性は共有）。直接加工の古い岩は形状ごとに同程度のコピーが必要。これはGPU/CPUの全メモリ実測値ではない。
- 3配置・2共有モデルの任意書出し例は約502KB、gzip参考約94KB。通常と行列加工では同じモデルを共有し、配置ごとの全頂点を重複して書き出さない。
- 固定森林／遺跡は今回のPC単回計測で約9.05秒／7.03秒。同梱bundle復元・TAB移動後の岩再処理は両方0回。起動時の最長long task458／452ms、TAB移動中173／137ms。速度改善や無停止の保証には使わない。

固定森林・遺跡は生成元の物理処理と元メッシュが不変であることを照合し、完成データのキー以外を変更しない。`tools/cave/rekey-walls.cjs` は基準版専用で、将来の生成元変更へ無条件で再利用しない。

比較画面は `tests/cave-wall-view.html`。検査は `node tests/cave-wall-validation.cjs`、`node tools/build-prepared-samples.cjs --check`。Unity検査は `tests/CaveWallChecks.cs` を隔離プロジェクトのEditor側で実行する。

## 残る制限

基本壁を同じ向きで大量に並べた柱状の反復は完全には解消しない。既存の斜割れ・段状肩を混ぜる配置を推奨する。壁専用の新しい内角・外角、天井、ゲーム本体統合、スマホ実機、Unity D3D12は未検証または未実装。Web/Unityの接地上限は既存0.15を維持し、廃案の0.35試作を含めない。

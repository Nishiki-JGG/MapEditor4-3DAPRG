# 汎用ボス扉2種（2026-11-07）

## 使い方

「小物を置く」→「建物・道具」に追加した、全マップ共通の独立した閉扉です。洞窟・草原・遺跡のいずれにも配置できます。遺跡部材のテーマや設定は変更していません。

- **ボス部屋の扉**: 厚い灰色の石板、巨石の門柱と横梁、中央で分割した八角形の石紋章。実測の幅約5.50m、高さ約6.15m。
- **ダンジョンボスの扉**: 青みのある鋼、真鍮の縁取り、大型蝶番、留め鋲、尖頂と分岐レリーフ。実測の幅約6.16m、高さ約7.26m。
- 向きと縮尺は配置ツールで変更できます。建築物として意図した寸法を保つため、ランダムな縮尺・回転の影響は受けません。
- Webでは閉じた状態の小物です。Unityではインポート時に固定枠と左右の扉葉に分かれ、開閉できます。鍵やボス戦開始などの発動条件はゲーム側から接続します。壁を自動でくり抜く機能もありません。既存壁と重ねず、通路の開口位置へ配置してください。

## 形状・素材と改善

制作時に石造門と重厚金属門の目標画像を個別に生成し、実際のWeb/Unity描画と比較しました。門枠の重量感、扉の中央継ぎ目、厚み、蝶番、閾を共通の機能として維持し、石は水平な大きい輪郭、金属は尖頂と真鍮装飾で見分けられる構成です。リポジトリには実装形状と再現可能な検証用ビューを保存しています。

初版では石の扉葉が暗すぎて金属に見えたため、灰石色・石板厚・浅い欠け筋を追加。続いて石目が縦に伸びるUVを修正しました。金属は実エディターの影側で装飾が暗く潰れたため、鋼色と金属度を調整しています。架空の発光による補正は使っていません。

自己評価は最終実画像を基準に **91/100**。内訳は用途と二種の識別19/20、重量感と構成19/20、材質と暗部の読みやすさ17/20、背面・俯瞰・接地18/20、実装互換と資源量18/20です。写実的な傷や彫刻の細密さより、既存の低ポリ表現と配置時の読みやすさを優先しています。画像目標の細部すべてを再現したという評価ではありません。

## 資源と互換

- 石: 3,080三角形。金属: 6,656三角形。
- 共有材質1つ。共通256×256の色とPBRの2テクスチャ。
- 新規Unity拡張 bossDoorsV1 は約2.71MBのJSON、gzip約403KB。小数6桁で出力し、位置の丸め誤差は最大0.5µmです。
- 既存サンプルの準備キーは変更前と完全一致し、出力専用変更では事前計算を無効化しません。
- 既存167種のID順は変えず末尾に追加。自動生成・散布には混ぜません。
- 既存の保存形式と共有素材ライブラリーを維持。Unityでは同じ頂点・UV・PBR情報から2 prefabを作成します。
- 閉じた扉はWebでメッシュ投影、Unityで枠と左右扉葉それぞれの同一形状のMeshColliderとして通行を遮ります。中央の細い継ぎ目はプレイヤー幅のSphereCastで確認しています。

## Unityの開閉（追補）

再インポートで生成する2種類のprefabには `MapSharedProps.BossDoorController` が自動で付きます。既存の静的prefabは新しいインポーターで再生成してください。Web保存形式・出力JSON形式は変えていません。旧v1の扉出力もそのまま読めます。

- `Open()` / `Close()` / `Toggle()` / `SetOpen(bool)` をゲームイベントから呼びます。Inspectorのコンポーネントメニューからも試せます。
- 標準は1.5秒、左右100度。Inspectorの Duration / Open Angle で調整でき、`Duration` は実行中も変更できます。0秒なら即時です。
- `SetOpenImmediate(bool)` は即時変更やゲーム側の保存状態復元用です。`OpenAmount`、`IsOpen`、`IsMoving`、`TargetOpen` で現在の状態を確認できます。
- Start Open は開始時の開状態です。途中で指示が反転しても現在の開き具合から滑らかに戻ります。コンポーネントやオブジェクトが無効な間は停止し、再有効化で続行します。
- 枠は固定、各扉葉のメッシュと衝突形状が同じヒンジで動きます。開いた扉葉の後ろに、閉状態の不可視コライダーを残しません。半開きの扉には衝突が残ります。
- アニメーションはFixedUpdateとゲーム時間に従います。ゲーム全体の保存・鍵・ボス戦・ネットワーク・NavMeshは変更していません。開閉状態をゲームのセーブに残す場合はゲーム側で状態を保持し、ロード時にSetOpenImmediateを呼んでください。
- v1造形の連結部品を左右別に分割し、元の全三角形・色・法線・UVを保持します。将来別形状を追加する時は、このv1専用分割契約を更新してください。

### 開閉検証

Unity 6000.6.8f1で、2種類×3配置（向き0/37/90度、縮尺0.75/1/1.4、Y倍率1.1）の6個を実際のPlay Modeで検証しました。開閉の進行、開状態の中央通行、閉状態の衝突、枠の衝突維持、途中反転、連続指示、即時変更、0秒、無効化と再開が成功しました。prefabとsceneの保存再読込後にもコンポーネント参照と各部品の衝突形状が保持されました。

閉姿勢の全三角形と属性を比較し、原点移動の浮動小数誤差を2µm以下として一致を確認。正面・背面・俯瞰6枚と開状態2枚を描画・確認しました。C#の事前コンパイルとUnityの再コンパイルにエラーはありません。検証環境には既存のUnity SearchDatabase起動時例外がありましたが、扉のPlay Mode検証は最後まで成功しました。Player buildと動的キャラクターの押し戻し・挟み込み処理は今回の確認範囲外です。

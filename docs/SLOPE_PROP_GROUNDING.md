# 低い小物の斜面接地と中央線の修正（ローカル検証済み）

対象は既存ID `shells`（貝殻・ヒトデ）。保存マップの互換性を維持する接地修正です。

## 接地と形状

従来は高さ約3cmの小物にも一律5cmの沈めが入り、水平のまま置かれていました。対象だけ沈めを1mmに変更し、描画地面と同じ三角形補間の支持面へ合わせます。貝4個は個別剛体。ヒトデ全体を剛体にした試作では凹凸境界で26.83mm浮いたため、腕5本を傾け、付け根の位置を共通に固定しています。

中央の黒い細線は、元の箱形状の面が同じ位置で重なるためでした。腕の中央側を薄くし、薄い中央部を加えてその面を覆いました。今回の限定形状修正で180→220三角形（+40、約22.2%）。最大外寸、原点、カタログ103種、保存ID・配置は維持。4個の貝の頂点・色・法線は変更前と完全一致します。中央部は最初の腕と同じ描画枠に含め、材質や描画枠を増やしていません。

配置・移動・回転・倍率変更・地形編集時に計算し、地面の変更領域と姿勢をキャッシュします。プレビューも同じ計算。固定高さp[7]を指定したものは追従させず、木や建物も一律に傾けません。全頂点を毎フレーム書き換える処理はありません。

## 負荷

ブラウザは腕5・貝4の9 InstancedMeshを共有。従来比+8回は**1組ごとではなく、通常表示の1描画パス全体**です。プレビュー・ゴースト表示・影は別パス。1/100/500組で描画回数は同じでした。不透明1材質・追加画像なし。

500組で110,000三角形、行列/色バッファ350,208バイト（容量512）。ユーザーPC Chromeの検査では初回再構築25.1〜44.7ms、キャッシュ使用時1.095〜2.81msと変動しました。定位置20回更新で追加接地計算/サンプリング0回。スマホ実機性能やGPU時間は未測定です。

Unityは9部品の接地済み姿勢を取込時に1組1メッシュ／1 Rendererへ結合。共有1材質、660頂点/220三角形、概算メッシュデータ約33KB/組（CPU/GPUコピーや管理分は別）。独自Updateはありません。配置ごとに姿勢が違うため、結合メッシュは配置ごとに持ちます。

## 保存とUnity

保存形式とID・原点・配置座標を維持。旧形式マップでも対象の接地を再計算するため、埋まっていた小物の見た目の高さは改善されます。

対象があるUnity書出しに任意の `grounded_props.json` を追加。元のCSV位置・yaw・scaleを照合し、不明版/部品IDや不正数値を拒否します。任意ファイルがない旧書出しは従来どおりです。

エディタとUnityの既存高さマップは解像度/補間が異なるため、小物の書出し姿勢だけを量子化後R16地面へ合わせ直します。地面や水そのものは変更しません。標準インポーターで56資産と接地3組を取り込み、D3D11描画と実TerrainColliderで確認しました。結合後の頂点と書出し姿勢の誤差は最大約0.0014mm。凹凸例の支持点差はブラウザ−1〜+4.88mm、Unity約−1.05〜+9.80mm。急な段差へ剛体を完全に密着させるものではありません。地形変更後は再書出し・再取込が必要です。

## 完成サンプルの整合

上流973fa00の岩・地形・通路・水・他の配置を維持しました。全再生成した候補には配置角度4.4e-16程度、変換行列7.1e-15程度の末尾差が出たため、その差を持ち込まず、上流の完成済みsnapshot/collision/profileをそのまま再利用し、現在の識別キーだけを更新しました。完成サンプルにshellsはありません。起動時の岩再処理はしません。

開発側の再確認手順は `node tools/build-prepared-samples.cjs` → `node tools/repack-slope-samples.cjs` → `node tools/build-prepared-samples.cjs --check`。再梱包ツールは今回の973fa00を対象とし、元メッシュや衝突部品が変わると拒否します。普段のプレイヤー読込時にこの処理は走りません。

森林/遺跡とも上流と全snapshot・collision・profileを厳密比較して一致。各々の正式なapp/index/manifestで読み、復元後の保存データ（岩形状含む）と通行判定も完全一致。TAB移動中のfit呼出し0回、岩差替えなし、保存再読込と不正キャッシュからの同梱復元も確認済みです。

最終のPC読込は森林約8.4秒、遺跡約6.5秒。初期処理の最長long taskは約424/421ms、TAB移動は約130/159msを観測。以前の長い岩再処理はありませんが、すべての短い停止が解消したとはしていません。2本の圧縮データ合計8,328,226バイト、配布JS合計11,104,430バイトで既存とほぼ同じです。

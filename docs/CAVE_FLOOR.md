# 洞窟床・第二バッチ

第一バッチ `e274f9d` からの差分。ローカル制作・検証のみで、push・公開は行っていない。

## 変更と使い方

洞窟の標準床は乾燥地と同じ大きな多角形亀裂を描画していた。洞窟だけを細粒堆積物と露出した石灰質岩盤へ変更し、数cmの埋もれた粒と低コントラストの色むらを加えた。初案は明暗の斑点が強かったため、同じカメラの実画面で比較し色差を抑えた。新しい画像は使っていない。

乾いた状態が標準。「岩壁を塗る」の「濡れた岩壁」を指定した洞窟床には、その領域内で不規則な湿りを付ける。局所的に最大24%暗くし、粗さも少し下げる。水の計算は変えず、洞窟奥へ苔を自動追加しない。既存ツールの説明も合わせた。洞窟以外の床は従来の描画を使う。

正本は `tools/cave/floor-surface.glsl`。`node tools/cave/build-floor.cjs` がブラウザGLSL、Unity HLSLと照合用契約を出力する。`--check` で生成結果との一致を確認できる。

既存rubble塗りの色と微小な法線用高さだけを変える。地形頂点、塗り判定、移動速度、衝突、通路、保存マップ形式は不変。gamma色を一度だけ `pow(rgb,2.2)` 変換する。表示上の凹凸は3.5mm以内で、実際の床は変形しない。

洞窟の書出しだけ `shared_ground.json` に任意の `caveFloor.version=1` を付加し、既存塗り・湿り指定を `cave_floor_mask.png` に収める。従来のmaterialVersion 2/3は維持。Unityは計算元SHA-256とマスク寸法を検証する。旧JSON・非洞窟では新機能を有効にしない。これは洞窟床レイヤーの材質検証であり、既存の全床レイヤーをUnity側で再実装する変更ではない。

## フローストーンの影

共有影パスが標準URPのshadow biasを適用しておらず、曲面に点状の自己影が残っていた。フローストーン材質だけ `CAVE_FLOW_SHADOW` を有効にして標準biasとnear clip処理を使う。全体の光・shadow設定、木や他材質は変えない。影を無効にせず、同一カメラの前後で点状の筋の改善と落ちる影の維持を確認した。

## 検証・負荷

- ユーザーPCの専用Chromeで床752項目：735地点の通行、保存・高さ・塗り・頂点の不変、局所湿潤の実ツール、保存読込、他バイオーム、書出し、shaderエラーなし。
- 第一バッチの83項目も再通過：旧103種の順序と旧保存、旧石筍衝突・3,030地点の通行、配置・回転・削除・非均等拡縮・静止する岩・共有書出し。
- Unity6000.5.9f1/D3D11の隔離プロジェクトで16,472項目：旧床JSONの互換、不一致契約の拒否、マスク設定、GPUの色・湿り・微小高さの比較。今回の2,048サンプルでブラウザとの差0。3素材が画角内にあることを検査し、真上・歩行・低視点と影補正の前後を撮影。
- 固定森林／遺跡はキャッシュなしで約9.36／6.33秒、同梱bundleから復元。TAB後の岩再処理は両方0回。最長long taskは起動時321／776ms、TAB移動中186／187ms。無停止や起動高速化を主張しない。
- 比較用3素材シーンは45,554三角形・13描画のまま。プログラム数71→71。新しいモデル・画像・ブラウザの描画パスやテクスチャは増やしていない。
- 最終計測後半では旧床GPU約1.76ms／新床約1.66ms、CPU描画命令投入約2.02ms／1.92ms。先行計測には初期化等のばらつきがある。専用PCの小さなシーンの値で、スマホ性能の保証ではない。
- ブラウザ追加コード約2.3KB。Unityでは洞窟材質にマスク1枚を追加。24mの例は49×49・PNG244バイト、非圧縮GPU参考約9.4KiB。大きなマップでは既存地形解像度に従って増える。モデル・材質数・配置バッファ数は第一バッチから増えない。

固定森林・遺跡の完成データはキー以外不変。`rekey-floor.cjs` は今回の描画・書出し・説明変更を逆変換したapp/indexが第一バッチと完全一致し、他の生成元が不変であることを確認してからキーを更新する。基準版専用なので将来の版に無条件適用しない。

## 再確認と制限

`tests/cave-kit-view.html` の「旧床」で比較する。検査は `node tests/cave-floor-validation.cjs`、`node tests/cave-kit-validation.cjs`、`node tools/cave/build-floor.cjs --check`、`node tools/build-prepared-samples.cjs --check`。Unityでは `tests/CaveFloorChecks.cs` と `tests/CaveFloorProbe.shader` を隔離プロジェクトのEditor側で使う。

勾配0.35（約19度）では裾の浮きを実見した。0.35追従試作はUnityとの整合操作が実行前拒否されたため採用していない。試作は作業ツリー外のパッチへ退避し、現用Web/Unityの上限は両方0.15で一致する。`steep-after.png` は未採用試作の画像。急斜面・段差・複雑な凹凸は引き続き制限。

スマホ実機・ゲーム本体への組み込み・Unity D3D12は未検証。両エンジンの照明・露出差を全体のライト変更で隠していない。

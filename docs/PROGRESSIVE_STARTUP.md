# 起動時の画面表示と素材読み込み

通常起動は空の平面。HTMLの操作枠・準備中表示を先に出し、平面の描画準備後に重い素材データを取得する。右下に件数ベースの進捗と失敗時の再試行を表示する。

- 地形・カメラ・保存は素材の全準備を待たない。配置パレットは未準備の素材だけ無効化する。
- データ12ファイルの取得後、167種類の形状を1種類ずつ準備し、処理の間にブラウザーへ制御を戻す。
- 保存済みマップ・サンプルの復元、Unity向け書き出しは必要な素材の準備を待つ。
- 素材取得失敗時も地形編集を続けられる。再試行では取得済みデータと準備済み形状を再処理しない。
- 画面表示に必要な本体コードと初回シェーダー準備は残るため、平面が瞬時に描画されるという保証ではない。その間も準備中表示を出す。

## 素材追加時

`node tools/generate-startup-metadata.cjs` で `props/shared/startup-metadata.js` を再生成する。これは名前・寸法などの一覧で、メッシュ・テクスチャ本体は含めない。生成元は shared/assets.js と shared/cave-decor-data.js。

遅延対象スクリプトは index.html の application/x-map-asset。追加モジュールがデータを初期化時に固定参照しないことを確認する。既存サンプルの data-preparation-key は読み込み方式だけの変更では変えず、形状と通行条件の照合を維持する。

## 確認

`node tests/startup-progressive.cjs`

実Chromeで素材通信を3秒遅延、別ケースで503にする。平面表示・地形編集・保存、未準備素材の配置防止、準備後の配置、再試行後の人物復帰、既存サンプル5,761配置物・552加工岩の完成済みデータ復元を確認。両ケース合格、JavaScript例外・WebGLエラーなし。

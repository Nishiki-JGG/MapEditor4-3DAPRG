# Grounded wood-and-iron mining tools

Actual images of the sack, haystack, coiled rope and mining tools were compared. The pick and shovel had uniformly coloured angular handles and a thick pyramidal shovel face. The other three props are retained. The selected miningtools ID keeps its two independent ground-fitting parts, placement pivots, length, width, role, scale range, nonblocking radius 0 and height metadata 0.16m.

The handles now sample the existing shared wood-atlas strip along their length. Ten-sided sections, a grip ferrule, a head collar and small fasteners clarify the joints. The shovel is an 8mm solid cupped sheet with a narrow worn bevel and supported neck, rather than a chunky centre fan. The pick head outline is retained. Triangle count is 200 to 416. The shared atlas PNG is byte-identical; no texture allocation or light is added. One shared Web material uses the established opaque prop path with that atlas instead of leaf-card lighting. This is stylized wood and forged iron, not a new PBR-metal shader.

Native ground-part recombination previously discarded miningtools UVs. SmallPropsV1 now preserves their original order and applies the same atlas V flip as the prototype; the existing rope branch retains its unflipped fibre coordinates. This is a targeted importer correction, not a schema or ID change. The baseline Reader was actually run before the correction and generated all 43 Prefabs from the new data. It accepts the geometry and placement but does not provide the corrected wood UVs on grounded instances. Reimport with the updated Reader for that appearance.

Web save/reload, finite data, nonblocking Collider output, unchanged grounding identities/placement, all unrelated small-prop data, the shared atlas and complete fire export passed. The final Web export equals the payload used in Native tests. Unity 6000.5.9f1 / URP17.5 generated 43 Prefabs, verified all 42 unrelated cached meshes, no tool Collider or light, and grounded-instance UV equality to the prototype. Both tool and barrel reference the same atlas object. Source game scenes were not saved.

Close views, opposite light and the existing generated grassland seed 71421 were reviewed with fixed A/B conditions. The material/joint improvement is strongest close up and subtle at normal game distance; the size was not enlarged to exaggerate it. Web still shows thin-blade self-shadow bands at some light angles. Small shadow-inset/bias trials did not resolve these sufficiently and were rejected; shadows, scene lighting and exposure were not disabled or globally changed. Native close views show a clean blade. Player, complete gameplay and Native GPU timing were not executed.

Reproduce Web with MINING_REVIEW_PROJECT set to a dedicated review project, then `node tests/mining-tools.cjs before`, `after2`, and `final`. The final step checks byte equality to Input101-after2. With the existing importer and shaders, copy tests/unity/Tools101Checks.cs into the dedicated project's Editor directory and run Tools101Checks.Run in background Editor batchmode. Use fresh Imported101-after3 output. Review checks and the recorded baseline Reader hash in tests/MINING_TOOLS_RESULT.json. No Player build is required.

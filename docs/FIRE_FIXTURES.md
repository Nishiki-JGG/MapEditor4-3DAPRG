# 松明の描画改善と地面置き篝火

建物・道具の既存「松明」と「壁掛け松明」を改善し、別ID `brazier` / `tdj/brazier` の「篝火」を追加しました。篝火は地面置きの三脚鉄鉢です。元ゲームの壁用Band1WallBrazierを地面用として流用していません。

## 形と火

既存松明の固定円錐の炎を除き、木の柄、巻き留め、鉄の籠、焦げた燃料と小さな熾火を作り直しました。篝火には荷重を受ける三脚と足、鉢と縁の鋲、交差した薪と木口、灰の炉床、炭、赤い熾火を作っています。松明1050三角形、篝火2688三角形です。

火は3枚の交差面をインスタンス描画し、流れる密度と透明な輪郭、細い炎の舌、明るい根元を描きます。個体IDごとの位相で揺れをずらします。煙は炎の上から薄く広がり、火の粉は上昇して消えます。壁掛けもWeb表示を同じ透明炎へ改良していますが、元ゲームのRoomTorch Prefab/VFXは変更していません。Unityへの原本復元は従来どおりです。

## 保存・Unity

旧保存データの `torch` は同じIDのまま読み込みます。篝火はタイプ表末尾へ追加。通常の配置・回転・倍率・削除・Undo/Redo・保存再読込に対応します。元松明の接地高さを保ち、CSVへも既定の沈み量0.05mを明示してWeb表示と一致させています。

Unity書き出しは新しい `fire_props.json` に本体の頂点・法線・頂点色・熾火値とVFX設定、個体の位置・向き・非一様倍率・初期化キーを保存します。`FirePropsBuilder` が同じ形と材質を生成し、透明炎shaderとParticleSystemを組み立てます。`MapSharedPropsBuilder` へ接続済み。追加された `MapSharedProps` のスクリプトとshader一式をUnityへコピーしてください。元壁掛けだけは引き続き元GUID/ハッシュのPrefabを復元します。

新2灯具と元壁掛けのUnity光源予算を同じ `RoomTorchBudget` にまとめ、6灯・影付き2灯を上限にします。部屋グループごとの予算であり、ゲーム全体の部屋横断予算への接続は今回含みません。

## 描画と確認

Webは炎1・煙1・火の粉1の3バッチを共有し、個体数によるVFX draw call増加を抑えます。光源は従来の6灯を共有。粒子は18〜32mで滑らかに抑え、遠方では停止します。本体と炎は残るので突然消えません。既存完成サンプルの衝突用fingerprintを保持し、形の描画改善で地形を再生成しません。手動配置専用の篝火は完成サンプルの生成入力に加えていません。

Windows/RTX 4070 SUPER、1280×720の実Chromeで1/10/50個混在を測定。Web更新+描画CPU中央値は約1.8/1.9/2.0ms、VFX更新中央値は計時分解能未満/計時分解能未満/約0.2ms。50個で10 draw calls、約8.1万三角形、約790粒子です。これはスマートフォン実機の性能保証ではありません。

比較は `output/playwright/fire-quality/` に保存。改善前→第一版→第二版→最終版を実描画し、薪の向き、炉床の白飛び、煙の発生位置と消え方を修正しました。Web旧保存互換、篝火の実UI配置・回転・倍率、削除Undo/Redo、保存再読込、CSV出力整合、完成64m/48mサンプル・TAB4回の再生成0を検査しています。

検査: `node tests/fire-quality.cjs`、`node tests/wall-torch-regression.cjs`、`python tools/preflight-wall-torch.py <Unity Editor/Data>`、隔離Unityの `FireQualityChecks.Run`、終了後の `python tools/check-wall-torch-log.py <証拠フォルダ>`。Unityは既存の共通ラッパーと再実行方式レビューを通してください。

隔離Unity6000.5.9f1/URP17.5の実検証も合格。実Web出力から3灯具を取り込み、外側Prefab保存再読込、頂点配列・材質・位置・角度・非一様倍率、両粒子のrateと初期化の再有効化復元、昼暗所・近距離・見下ろしを確認しました。全起動ログでseed Assert0、C# error0、Shader error0、新規例外0。既知のEditor SearchDatabase例外1件は全stackを別記録しています。

## 制限

WebとUnityでは粒子の乱数・ノイズ・ライティングが異なります。火の3交差面は体積シミュレーションではなく、真上では交差面の構造が見える場合があります。煙は深度を使うsoft particleではありません。Webでは点光源の影を増やさず、既存の太陽影と本体の接触陰影を利用しています。スマホ実機・Playerビルド・元ゲーム本番シーンへの統合は未検証です。

# Sea-fan net readability

Twelve remaining small props were compared at a fixed Web distance: crystal, obsidian, glowing mushroom, iron fence, rubble pile, stalagmite, magic circle, fumarole, bone pile, skull pile, sea fan and staghorn coral. The top candidates were the sea fan (fine repeated holes obscured the supporting branches), fumarole (opening read as a bright flat disk), and obsidian (black diamond silhouettes hid the glass-like faces). Only the sea fan is changed here. The other findings are visual candidates, not claims that their implementation has been fixed.

The existing sea-fan surface generator uses larger irregular cells and slightly wider connecting strands. This reduces the dense grid appearance and exposes the hierarchy between the sculpted main branches and the fine net. Cell radius changes from 0.018 to 0.030, node jitter from 0.70 to 0.95 of cell radius, and stroke width from 1.05–1.35 to 1.35–1.70 pixels in the same 256-square texture. These are deterministic texture-space changes, not extra branches or a change of species, scale, placement or use.

All 1,106 triangles, vertices, normals, colours, UVs, bounds and collision settings are exact. The surface ID, PNG dimensions, filtering, alpha threshold, colour space and schema remain unchanged. The existing importer reads the new PNG through the same contract. No new texture, material pass, light or additional asset ID is introduced. The main atlas and all non-sea-fan native payloads, including chests and fire, are byte-identical.

## Verification

Set SEAFAN_REVIEW_PROJECT to an isolated evidence directory and run `node tests/seafan-net-readability.cjs before` and `after`. The baseline is cc812e4. Images, surface PNGs and importer inputs are local outputs. The test compares real collision Map/Set contents and export payloads, not JSON.stringify(Map) empty objects. Set PROPS_LOAD_OUT and run `node tests/seafan-net-load.cjs` for normal and legacy saves of rotated/scaled placements, 44 mixed types and bounded 9/225 instance checks.

In the existing dedicated Unity 6000.5.9f1 / URP17.5 project, retain baseline prefabs under Assets/Imported109-after-v3 and supply Input111-after from the Web test. Copy Fan111Checks.cs, Fan111Review.cs and ColliderSnapshot109.cs into an Editor folder. Run Fan111Checks.Run in background batchmode. It imports all 43 prefabs to Assets/Imported111-after-v3, or rechecks completed output without rebuilding it. Retained Imported104-after is used for the prior banner collider correction. Actual MeshCollider geometry, settings and transforms are compared with nonempty assertions and mutation/removal negative controls. Display mesh equality compares vertices/indices/normals/colours/UV, rather than cache GUID: the existing cache key includes the surface PNG, so equivalent mesh data can have a new asset identity.

The first test attempt retained an old output-folder name and stopped before successful asset creation; the harness was corrected. The next attempt completed import but incorrectly asserted display-mesh reference identity. It was corrected to compare actual mesh attributes, then passed using those completed prefabs. Neither test failure was masked as a product pass.

Unity near and opposite-light images retain the open fan outline and supporting branches while reducing the tight repeating mesh pattern. The existing isolated production grassland generator, seed 71421 and normal camera offset (0,9,-6.3), was used to judge normal-distance readability in actual lighting. It is a camera/lighting comparison, not evidence of a sea-fan habitat or marine gameplay session. Web and Unity retain the thin stylized cutout limitation; this is a targeted material/readability improvement, not a new high-detail coral model.

Renderer resource counts and bounded timing samples are recorded in validation/seafan-net/results.json. No mobile, Player or complete interactive gameplay performance claim is made. Large images, export data, private game scenes and machine-specific paths are not published. Concurrent water/ice and all earlier small-prop improvements are preserved.

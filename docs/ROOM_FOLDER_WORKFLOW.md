# 部屋フォルダの保存と凸ダンへの受け渡し

目標は、作成した部屋を凸ダンの候補に登録し、Seedで選んで小マップ間をワープ移動するランダムダンジョンで使うことです。地図を物理的につなぎ合わせる方式ではありません。

## 制作者の操作

1. エディタで地図を作り、出入口、開始地点、敵・宝箱の候補を設定します。
2. 地図名を付け、「部屋セットを保存 (JSON＋ZIP)」を押します。
3. ダウンロードされた `地図名_room.zip` を展開します。
4. 展開された部屋フォルダを保管し、「このフォルダの部屋を凸ダンに取り込んで」と指定します。

展開後の部屋フォルダには、再編集する `地図名.json`、同じ編集状態の `地図名_export_unity.zip`、保存の説明が入ります。内側のUnity用ZIPは展開する必要がありません。再編集した場合は部屋セット全体を保存し直してください。異なる日時のJSONとZIPを混ぜないでください。

既存の「保存 (JSON)」「Unity用書き出し」も使用できます。部屋セットはブラウザのフォルダ書き込み権限に依存せず、ダウンロード1回で両方を持ち出せます。検証エラーのある制作途中でも保存できますが、本体用の受付ではエラーを解消する必要があります。

## 開発側の受付

リポジトリの `tools/receive-room.py` を使います（Python標準ライブラリのみ）。

```powershell
python tools/receive-room.py "C:/Maps/森の部屋"
python tools/receive-room.py "C:/Maps/森の部屋" --output "C:/Maps/取り込み用/森の部屋-v1"
```

原稿とZIP内の原稿、部屋ID、manifestの全ファイルのSHA-256、書き出し全体のハッシュ、エディタ検証エラー、出入口を確認します。保存履歴の `revision` と `lastExportHash` だけは比較対象外です。形状・塗り・小物・出入口などはすべて一致が必要です。

`--output` は新しいフォルダだけを受け付けます。すべて確認してから `source.json`、`export/` 内のUnity入力、`intake.json` を公開します。既存資産は上書きしません。不正な展開先・重複ファイル名を拒否します。

## 現時点の対応範囲

- 実装済み：部屋セット保存、原稿と書き出しの一致確認、Unity入力の受付・展開。
- 凸ダン既存機能：取り込み済みPrefabへの出入口・配置候補の付与、既存2種類を使ったSeed生成・ワープ往復の試行。
- 未完：任意の書き出しから地形・全小物・水を揃えた本体Prefabを作る一括取り込み、任意の部屋候補カタログへの登録、通常探索・戦闘・保存との接続。

受付結果の `source_ready` は「原稿を取り込み工程へ渡せる」という意味です。ランダムダンジョンで遊べる状態の完成判定ではありません。

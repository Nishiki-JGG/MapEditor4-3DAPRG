# 部屋フォルダの保存とゲームへの受け渡し

2026-10-25更新：編集には「保存」、Unityへの受け渡しには「Unity用に書き出す」（[素材の自動同期](ASSET_REGISTRY.md)）を使います。以下の共通ZIP手順は従来形式・移送用として残しています。

目標は、作成した部屋をゲームの候補に登録し、Seedで選んで小マップ間をワープ移動するランダムダンジョンで使うことです。地図を物理的につなぎ合わせる方式ではありません。

## 「詳細な書き出し」を使う場合

1. エディタで地図を作り、出入口、開始地点、敵・宝箱の候補を設定します。
2. 地図名を付け、「編集データ＋Unityデータ（ZIP）」を押します。
3. ダウンロードされた `地図名_room.zip` を展開します。
4. 初回・素材更新時に「共通素材（ZIP）」を押し、ダウンロードした共通ZIPを部屋フォルダの親へ置きます。同じ版は1個だけ保管します。
5. 展開された部屋フォルダを保管し、「このフォルダの部屋をゲームに取り込んで」と指定します。

展開後の部屋フォルダには、再編集する `map.map`、同じ編集状態の `地図名_export_unity.zip`、保存の説明が入ります。内側のUnity用ZIPは展開する必要がありません。共通資産ZIPも一緒に受け渡してください。詳しい保存例と旧ZIPの変換方法は[共通資産の保存](ROOM_PACKAGE_STORAGE.md)を参照してください。再編集した場合は部屋セット全体を保存し直してください。異なる編集状態の原稿とZIPを混ぜないでください。

既存の「保存」「Unityデータのみ（ZIP）」も使用できます。部屋セットはブラウザのフォルダ書き込み権限に依存せず、ダウンロード1回で両方を持ち出せます。検証エラーのある制作途中でも保存できますが、本体用の受付ではエラーを解消する必要があります。

## 開発側の受付

リポジトリの `tools/receive-room.py` を使います（Python標準ライブラリのみ）。

```powershell
python tools/receive-room.py "C:/Maps/森の部屋"
python tools/receive-room.py "C:/Maps/森の部屋" --output "C:/Maps/取り込み用/森の部屋-v1"
```

新形式は別保存の原稿とZIP内 `source_ref.json` のSHA-256、旧形式は原稿とZIP内の原稿、部屋ID、manifestの全ファイルのSHA-256、書き出し全体のハッシュ、エディタ検証エラー、出入口を確認します。保存履歴の `revision` と `lastExportHash` だけは比較対象外です。形状・塗り・小物・出入口などはすべて一致が必要です。

`--output` は新しいフォルダだけを受け付けます。すべて確認してから `source.map`（旧形式は `source.json`）、`export/` 内のUnity入力、`intake.json` を公開します。既存資産は上書きしません。不正な展開先・重複ファイル名を拒否します。

## 現時点の対応範囲

- 実装済み：部屋セット保存、原稿と書き出しの一致確認、Unity入力の受付・展開。
- 連携先ゲームの既存機能：取り込み済みPrefabへの出入口・配置候補の付与、既存2種類を使ったSeed生成・ワープ往復の試行。
- 未完：任意の書き出しから地形・全小物・水を揃えた本体Prefabを作る一括取り込み、任意の部屋候補カタログへの登録、通常探索・戦闘・保存との接続。

受付結果の `source_ready` は「原稿を取り込み工程へ渡せる」という意味です。ランダムダンジョンで遊べる状態の完成判定ではありません。

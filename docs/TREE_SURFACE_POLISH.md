# 葉塊と樹皮の反復を抑える改善

372797f の根張り・葉塊改善を保ち、葉塊の向きと形の繰り返し、樹冠内部の浅い明暗、幹根の長い縦線を対象にした追加バッチです。新種・専用UI・動作システムは追加していません。

[同じカメラ・照明の変更前後](../tests/tree_surface_compare.html) / [実エディタで裸地・草地・斜面を確認](../tests/root_reference_view.html) / [本体](../index.html#size=64)

## 実際に変えた点

- 広葉樹 `oak`・ナラ `nara`・ケヤキ `zelkova` の葉塊を、別の固定乱数で大小・長短・向き・傾きに差のある形へ調整しました。14/19、20/25、20/25個の葉塊で形を変えています。外周の寸法を決める葉塊は形を保持し、模様の回転・反転と色調で変化を加えています。
- 樹冠の低い内側は深い緑、上側や外側は明るい緑になるよう、葉塊単位と面内の明暗を調整。枝と接続する中心を保ち、枝が見える隙間を残しました。全体の照明や彩度は変えていません。
- 溝の深い樹皮を使う8種（広葉樹・ナラ・オリーブ・柳・エルフの木・世界樹・枯れ木・異形の木）の既存128角セルを、長く連続する黒い線から、途切れた割れ目と重なる木肌の模様へ変更。幹・根・枝をまたぐ大きな色むらを頂点色へ焼き込みました。
- 普通の根張り・露出根・幻想樹の板根の形は372797fから完全一致です。全木を同じ根形へ戻していません。元の丸い密な茂み `bush`、水、地形、主人公、ID・原点・配置寸法・風接触パラメータを維持しています。

参照の方向は、前回確認した[UMDの正常な根張り写真](https://marylandgrows.umd.edu/2024/01/12/free-the-flare-maintain-visible-root-flare-for-tree-health/)と、ユーザーの目標画像・根元3写真について提供された実見記録を引き継いでいます。今回の樹皮は自作のデフォルメ表現で、各実物樹種を厳密に再現した模様ではありません。写真や透かしの画素は使っていません。取得制約のある添付やPDFを別経路で取得していません。

対象9モデル合計11,981三角形・11,400頂点は増減なし。各種1材質、7画像、1024×512共用atlas（RGBA8＋mip概算2.67MiB）を維持。atlasのalphaは全画素一致、広葉セルも変更なしで、128×128の樹皮RGBだけを変更しました。PNGは326,241→324,887 bytes（−1,354）。

メッシュ・UV・色の差が圧縮されにくくなるため、共有データは8,802,419→8,803,371 bytes（+952）、zlib圧縮は2,312,103→2,356,144 bytes（+44,041）。画像の減少だけを通信量全体の改善とはしていません。

真上に投影した葉面の合計は広葉樹+1.27%、ナラ−2.09%、ケヤキ−0.48%。これは全三角形を重ねた面積の参考値で、画面の透明overdrawやGPU時間そのものではありません。新たな葉板を追加せず、画像の透過率も維持していますが、重なり方・影は変わります。スマホ実機は未測定です。同じ森林1,204配置の実フレームは、前後とも31描画・596,270三角形でした。裸地2本は11描画、別樹種を追加した場合は12描画で、atlas共有だけで全樹種1描画にはなりません。

## 検証と限界

ユーザーPCのChrome/SwiftShaderで、真上90度と歩行補助視点、人物比、裸地での根元近接を同じ条件で比較。樹皮の連続した縦線と葉塊の向きの反復は減りましたが、21三角形を基本とする葉塊の輪郭や、近接での樹皮タイルの繰り返しは残ります。目標画像と同じ密度・写真品質に到達したとはしていません。

ソース保全2,253項目、再生成 `bake_roots.cjs --check`、本体24種の選択/配置/回転/削除/旧保存読込211項目、根付き24種の斜面・非均一拡縮96ケース、裸地/草地/境界・太陽オンオフ・縮尺96ケースを通過しました。全38可動モデルと根付き24種のGPU座標で無風一致、根幹固定、風と接触の合成、個体位相を確認。本体の変更9種と保全した茂み計10種で、風3プリセットの時系列画像、歩行接触・連続接触の上限・離脱後復帰を確認しました。

隔離Unity 6000.5.9f1/URP/D3D11では378項目と根元材質173項目を通過。50モデルの形状・法線・UVに加え、今回は頂点色の数値一致とatlas PNGの完全一致を確認しています。新旧エクスポート、GPU変形、影、裸地と緩斜面の根元を検査。Unityの検査照明はブラウザとは異なるため、照明まで含む画素一致を主張するものではありません。元ゲームは起動・変更していません。

接触CPUだけの参考値はユーザーPC Chrome/SwiftShaderの484配置・2,400step合計9.1ms、最大候補23。計時で0に丸められる値を無負荷とはせず、描画FPSやスマホ性能の証明にもしていません。既存の急斜面/急曲面に対する15%上限の局所平面追従、小縮尺の枝下、幹主体の簡易colliderと細根の差を引き継ぎます。元ゲーム統合、スマホ実機、Built-in描画は未検証。Unity D3D12終了時クラッシュは既知の未解決事項です。

[一覧](../tests/prop_refine_view.html) で真上・斜め・遠景と1.8 m人型を確認できる。種類は増やさず、最新main `3252d88` の84 ID・原点・外形寸法・配置設定を保った。

|---|---|---:|
| 倒木 log | 黒つぶれを抑えた樹皮、低く落ち着いた苔、浅い折れ枝、断面の色幅 | 284→242 |
| 切り株 stump | 的のような同心円を弱めた偏心の木口、細い割れ、不均等に曲がる根元 | 238→206 |
| 露出根 rootfan | 同じ中心から5方向へ伸びる形を、曲がる3本の主根と途中の分岐へ | 100→100 |
| 流木 driftwood | 直線の角材感を減らした曲がり、接続した折れ枝、冷たい退色の木肌 | 172→142 |
| 木の柵 woodfence | 面取りした横木、少し傾いた柱、明るい木口と小さな留め金 | 306→158 |

5種合計1,100→848三角形、252削減（約23%）。いずれも1材質・不透明。既存の設定上の高さ、配置半径、接触用のオフセット、タグ、許容傾斜、倍率、最小間隔を保持した。幹のある生木や花畑・風・接触は変更していない。

## 形状と素材

輪郭を低ポリのまま整え、約46度以下の浅い面のつながりだけ法線を平均した。木口と側面など大きな角度差は残す。苔は厚い明緑の塊から低いくすんだ起伏へ変え、共有頂点の位置を合わせた。年輪は強い色差の的にせず、木口の偏りと浅い割れで読ませる。細密な樹皮や年輪の新画像は追加していない。幹の節ごとに木目がリセットされる継ぎ目を近景で確認したため、幹・枝全体の距離に沿う連続UVへ修正した。

倒木・切り株・露出根は既存の `forest-atlas-v1` の樹皮と白領域を使う。流木・柵はブラウザ専用生成から共有資産へ移した。同じ見た目をUnityへ持ち込むため、既存の自作 `TDGeo.ATLAS2.paint()` の木材セルを256×256の共通画像 `weathered-wood-v1` にまとめ、白い木口用の帯を設けた。PNG86,289バイト、sRGB・trilinear・mipmap・異方性2。外部素材や原ゲーム資産は使っていない。以前の5画像はバイト単位で不変。

新画像は2種で共用し、各オブジェクトの材質数は1のまま。共有経路の材質実体は2種分増える。RGBA8＋全mipmapの画像本体は理論上約341 KiBだが、GPU実割当は測定していない。元の1024×512アトラスは他のオブジェクトが使うため削除しない。三角形削減と画像追加は別の負荷として扱う。共有JSは非圧縮で264,336バイト増、ローカルgzip比較で87,424バイト増（実配信の圧縮方式とは別）。

## 原点・互換性・共通化

5種すべてで、各軸の最小・最大座標を以前の値に合わせた。ブラウザ検査で誤差は1 µm未満。流木の最小Y約-.0517 m、柵の最小Y約-.0285 mも元の設置原点を変えないため保全し、地面へ少し埋まる下端として扱う。残る3種の最小Yは0。既存マップの座標を補正したり保存形式を変えたりしない。

共有ライブラリは `shared-plants/6`、30→32モデル、5→6画像。カタログは84のまま。新しい2共有モデルは既存ID `driftwood` と `woodfence` で登録し直すだけで、新規の配置IDは作らない。今回のUnity Editor取込コードも更新する。旧2/3/4/5ライブラリの読込を検査した。

水・主人公・地形・ブラシや履歴UI・旧サンプル・他27共有モデルと可動植物パラメータは変更していない。木の枝下クリアランスも対象外で従来値を保つ。柵の衝突は以前の簡易半径とオフセットのままで、横木に沿う精密な物理コライダーを追加していない。

## 検証

- ユーザーPCのChrome/SwiftShaderで、本体カメラの真上90度・通常17 m、補助の斜め・近景9 mを同じ照明・配置で前後撮影。現在の本体主人公を併置し、一覧は別の1.8 m人型を使う。
- ブラウザ102項目：全84 IDと順序、旧マップ配置、選択・分類・配置・削除・回転・全体／縦拡縮・保存読込、外形寸法と設定高さ、共有書出し・CSV丸め誤差。
- 元の5画像と対象外27モデルの全データ不変、正常な法線、UV範囲、面積0の三角形なし、設置原点、各材質・動かない設定を確認。
- 一覧の初回表示、真上・斜め・遠景・単体、材質読込、風設定を変えても静止画像が同一であることを確認。
- 18種の可動植物について実WebGL2の頂点を読み戻し、元の風・接触・合成変位上限・根元固定・回転拡縮・位相差を維持。花畑の配色と動きを変更するコードは含まない。
- 隔離Unity6000.5.9f1 / URP17.5 / Direct3D 11で92項目（終了コード0）：32モデル・7配置・18種のGPU照合、2接触登録、旧2/3/4/5の取込、ForwardとShadowのコンパイル、5種の実描画を検査。静的5種の時系列画像は完全一致。

最初のDirect3D 12実行は92項目成功・画像保存の後、終了時にネイティブアクセス違反（0xC0000005）となった。同じ検査をDirect3D 11で再実行して正常終了した。描画APIに関係する可能性はあるが、Direct3D 12側の根本原因は未確定。製品やゲームの描画設定は変更していない。

スマホ実機、全体FPS、GPU時間、ゲーム本体への組込み、Unity Built-inは未検証。三角形を削減したことを実機性能の保証としない。根元の形状は平坦な基準面で整えたもので、急斜面へ自動追従しない。極端な接写では低ポリの輪郭と既存樹皮画像の繰り返しが見える。

## 再生成

生成元は `tools/nature/prop-refine.js`、コマンドは `node tools/nature/bake_prop_refine.cjs`。他の植物を再生成する場合は new → grass → understory → meadow → prop_refine の順で最後に実行する。旧 `tools/nature/bake.cjs` は古い地面・ライブラリを丸ごと書くため、このバッチの再生成には使わない。

検査は `prop_refine_source.py`、`prop_refine_validation.cjs`、`prop_refine_gpu.cjs`、`prop_refine_review.cjs`、`prop_refine_gallery.cjs`、Unity `PropRefineChecks.Run`。前後画像とログ・個別PCの検査プロジェクトはリポジトリ外に保存する。

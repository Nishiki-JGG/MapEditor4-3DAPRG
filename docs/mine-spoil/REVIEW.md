# 土砂 139–141：独立レビュー合格・公開準備

`mine_spoil` / `tdj/mine_spoil` を「坑道小物」に追加した。公開済み基点は `eb5803575fe8bd02cca37c70cae0c9ea586384d9`。既存小物・床・固定岩を置換しない手動配置専用の一品。公開済みレールドラッグは維持する。

## 調査と設計

USGS は掘削段階の廃石を、処理後の細粒尾鉱と区別している。今回は掘削土と角張った岩屑の混合物とした。[USGS](https://www.usgs.gov/programs/mineral-resources-program/science/critical-minerals-mine-wastes)

ISSMGE の鉱山廃石研究では、角張った広い粒径分布と、投棄時に粗粒が細粒より遠方へ移る分級が記述される。同研究の約38度は大規模堆積場の観測であり、この小物の万能な規格にはしていない。[研究論文](https://www.issmge.org/uploads/publications/1/21/STAL9781607500315-3421.pdf)

USGS の Brooklyn Mine 写真を実画素で観察し、細粒の母材、局所的な粗粒、広い斜面の不均一さを参考にした。機材や木材は対象外。写真をテクスチャへ転用せず、マップはコードから自作する。[参照写真](https://www.usgs.gov/media/images/brooklyn-mine-co-ert-profile-mine-waste-pile)

- 見た目の実測範囲：約2.125 × 1.640 × 高さ0.418 m。偏心した低山と不均一な裾。
- 合計400三角形、1200頂点。山体240三角形＋埋込みの角石8個160三角形を一つに結合。
- 大粒を片側の裾へ寄せ、粒径混合の色・法線・粗さマップと連動。写真素材なし。
- 512×256の3枚を全個体で共有。Webは色をsRGB、法線・粗さ等をlinear。Unityは標準URP/Lit、R金属/G AO/A smoothness。法線のUV縦反転補正は取り込み時に一度だけ。
- 頂点色は白、材質とテクスチャを保存資産へ保持。個体色を一時的なPropertyBlockだけに預けない。
- 標準Colliderは半径1.15m・高さ0.55mの円柱。非衝突、任意の正規半径/高さ、形状Colliderに対応。大きな土砂をレール中央へ置くと当然通路を塞ぐため、配置時に縮尺を選ぶ。

## 修正と自己レビュー

139の全周黒帯は上面と底面で平均化された法線が原因。140で法線を分離し、同じWeb条件で解消を確認。四角い粒模様も不均一な輪郭へ修正した。

140では立体石が周囲へ均等に散った印象が残ったため、141で粗粒を一方の裾へ寄せ、他の面は細粒を主体にした。面数は増やしていない。

実洞窟の横視点140にはカメラが既存壁の裏へ入った無効画像がある。元の画像を保全し、141では室内側の斜視を撮り直した。素材の明るさや既存壁を変更して隠してはいない。

自己評価91点に対し、独立レビューも **91/100（26/17/19/20/9）**、当該P1/P2なしで合格した。

## 検証

- Web: 有限頂点、単位法線、頂点溶接後の閉じた各表面、上下面の向き、床下頂点なし、標準円内への収容、保存復元の実Map/Set Collider内容一致。旧種類表の再対応。レール・トロッコ・掘り跡岩壁のexport内容一致。
- 通常UI相当: 選択、プレビュー、回転/縮尺、地表3.5mの下の坑道床0mへの配置、保存復元。入力は専用headless内だけで実行。
- Unity 140: 正常/欠落/未知version/範囲外index/不正PNG/非有限値/非衝突/compact/任意円半径/任意高さ/形状Colliderの11条件。正常50、不正時49。旧49の実meshハッシュと実Collider型・形状・姿勢を比較。保存→破棄→Prefab再生成で材質・mesh・姿勢を照合。
- Unity 141: 最終形状/マップを正式に再importし50種生成、旧49保持、保存後再生成、通常/近景/裏/反対光/点光/spot/無照明、9/225共有を再確認。140以降Importer契約コードは不変なので、全破損条件の無意味な再実行はしていない。
- 実ゲーム洞窟: 既存生成器のseed71421、648セル、既存21灯、通常距離/近景/斜視、明暗2位置。シーン原本は保存変更しない。レールは検証用に追加した正式Prefabで、元ゲームに既設だったという意味ではない。
- 製品坑道テスト: 長さ14m、幅2.4m、高さ2.8m、既存2灯。土砂scale0.25で壁際へ配置、床0mへ接地、車台・中央レール通路との非交差。実ゲーム既存レベルではなく製品の坑道生成器で作る確認用マップ。
- 9/225: Unity双方全数が視錐台内、1mesh/1material/3texture。CPU Render呼出し中央値約0.89/1.17ms。Web追加draw1、225個で追加90,000tri、texture数不増。CPU呼出し時間はGPU時間・実ゲームのフレーム保証ではない。
- レールドラッグ: 直線/左右曲線/閉ループ/端点/取消7条件/一筆Undo/保存復元。タッチ曲線、左＋右/中ボタン、静止ポインタ＋WASDの入力境界4条件も通過。
- 固定岩・prepared資産は基点とハッシュ一致、再生成0。水面・氷床は変更なし。

## 再現と残る制約

Web検証は `tests/mine-spoil.cjs`、`tests/mine-spoil-placement.cjs`、`tests/mine-spoil-load.cjs`。`MINE_SPOIL_OUTPUT` に証跡先、`MINE_SPOIL_BASE_FIXTURE` に公開済み49種のsmall_props.json、`MINE_SPOIL_INPUT` に新しい取り込み先を指定する。既存の未知追加データを保持したbaseへ土砂追加分だけを書き込む。

Unity検証は `Spoil140Checks.Run`（全契約）と `Spoil141Checks.Run`（最終表示/保存/負荷）、`Spoil141Field.Run`（製品坑道）。既存検証環境のShared117Review、ColliderSnapshot109、基点Imported137-validとInput123Mineを再利用する。実ゲーム洞窟の生成依存と専用ハーネスは公開エディタへ混ぜない。

Player・旧Readerバイナリ・スマホ・GPU時間は未実行。旧Readerの未知追加フィールド無視は従来ソース制御フローの確認のみ。傾斜/凹凸床への裾追従は非対応。非常に狭い通路では縮尺や配置位置を調整する。

合格後に最新mainの洞窟装飾20種を保持して統合。release/cache URLと固定サンプルkeyを同期し、完成した形状・配置・通行データはキー以外一致、固定岩再生成0。外部公開の結果は別の配信確認記録に残す。

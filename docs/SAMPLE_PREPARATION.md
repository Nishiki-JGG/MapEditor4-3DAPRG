# サンプル読込と崖岩の準備

サンプル読込後に歩くモードへ切り替えると、一度長く停止し、崖岩が上下2段へ変わる問題を修正しました。葉の照明変更ではなく、自動配置した崖岩の接地・通路検査と衝突用距離場の初回生成が、操作開始後にも走っていたことが原因でした。

固定サンプルの端末初回計算を省いた後続変更は [完成データの同梱](PREPARED_SAMPLES.md) を参照してください。以下の計測は同梱前の811e26dの記録です。

## 挙動

- 生成、岩の接地仕上げ、保護通路の検査、衝突準備、初回描画まで完了してから操作可能になります。途中で岩を差し替える予約処理は行いません。
- 準備中も経過時間・工程を表示し、中止できます。TABは希望するモードとして保持し、完了時に反映します。途中の状態は保存できません。
- 中止・連続生成・別マップ読込は世代で区別し、古いジョブが新マップへ結果を適用することを防ぎます。中止・検証失敗時は元の安定したマップへ戻します。
- 固定seedの完成サンプルと衝突情報を再利用します。サイズ・seed・biome・体格・カタログ・元モデル・処理／スクリプト版が異なる情報は使いません。地形編集後の加工無効化と、明示的な岩自動配置は別経路として維持します。
- 旧形式でIDがない未加工小物は従来どおりIDを補完します。加工岩は、そのID・元形状・入力・姿勢を照合します。保存形式は変えていません。
- 大きな保存JSONをサイズ変更後のページへ渡す際は、IndexedDBに一時保管し、sessionStorageには小さい識別子だけを置きます。サイズ変更前にも検証します。復元後は一時データを削除します。
- 初回シェーダー準備は非同期APIで待ちます。最初の描画も準備時間に含めます。初回の描画や初期データ構築には短い同期停止が残ります。

## 形状と負荷

崖岩の形状・上下2段の仕上げ・保護通路の採否を変更する修正ではありません。最近傍境界の距離は二乗値を比較し、最後に平方根を取ります。従来との4,064,555個のFloat32距離値・583個の距離場の一致も別途確認しました。

最新mainを基点とする比較では、固定seed7の5,761配置・加工岩552個を含む保存データ全体と、0.5m格子で調べた通行判定が変更前と完全一致しました。岩276個を仕上げ、17個を元形状のまま保持、7個を通路保護で差し戻す結果も同じです。並行更新の海・Unity用海シェーダー・乾燥土片は保全しています。

キャッシュはRAM1件、永続の完成サンプル1件です。ユーザーの保存ファイルを上書きしません。固定サンプルはブラウザの保存機能が利用できなくても配布済み完成品を読み直します。新しいランダムseedや編集した生成条件は通常の生成を行います。サイズ変更用の一時保存ができない場合は、現在のマップを保ってエラーを表示します。中断で残った一時引継ぎデータは、次の引継ぎ時に24時間以上古いものを掃除します。

メモリ上の費用もあります。代表例の衝突・距離場・輪郭の配列要素換算は約33.2MB、加工形状JSONのUTF-8表現は約36.7MBです。JSの文字列・配列の管理領域などは別途必要です。三角形・材質・画像を追加して描画品質を下げる方式ではありません。

## 検証

ユーザーPC上の隔離Chrome、1280×720、同一カメラ・同一サンプルで比較しました。OS／GPUドライバーのキャッシュは消去していません。単発の実測であり、スマホ実機の性能保証ではありません。

統合版の測定値（秒、最大long taskのみms）:

| 条件 | 完了時間 | 最大long task |
|---|---:|---:|
| 変更前の固定seed7 | 操作後まで後処理が継続 | 9,497（初回描画）／5,708（後段の採用） |
| 固定seed7、完成キャッシュなし | 14.63 | 522 |
| 同じサンプルをRAMから再利用 | 2.92 | 288 |
| ページ再読込後の永続キャッシュ再利用 | 3.33 | 282 |
| 新規平面からランダムseed23 | 10.70 | 493 |
| 48mサンプル2 | 6.42 | 個別の最大値は未集計 |

準備完了後の2.5秒の歩行では約9.8m移動し、岩の変化とlong task記録はありませんでした。これらは同じPC上の一例です。以前の試作では初回17〜25秒、ランダムseed23で47.6秒、最長0.5〜1.1秒の停止も観測しています。再利用できることと、初回・新しいランダム生成が即時に終わることは別です。

以下を実ブラウザで確認しました。

- 固定サンプルと平面・ランダムseed23・48mサンプル2、TAB・連続TAB・歩行。
- 生成完了後に岩が変わらないこと。保存再読込で形状・通行判定が一致すること。
- 不正な加工データの拒否と元マップ復元。IDなし旧形式と小さい縮尺の小物。
- 地形編集による古い加工の無効化。再生成時の完成キャッシュ照合。
- 仕上げ中の中止ボタン、連続生成で古いジョブを破棄すること。
- 約36.7MBの保存マップを48mページ経由で64mへ引き継ぎ、中間サンプルを生成せず復元すること。
- GL・シェーダー・実行時エラーがないこと。

Unity実行・スマホ実機は今回の検証に含みません。元モデル、共有資産とUnityデータの形式は変更していません。Windowsのチェックアウトでは、海の共有HLSLの単体検査がCRLFとLFの差だけで失敗するため、改行を揃えた読込でも一致を確認しています。海の製品ファイルは変更していません。

再現用（Node.js、Chrome/Edgeが必要）:

```powershell
node tests/preparation.test.cjs
node tests/fits-store.test.cjs
node tests/contact-math.test.cjs
node tests/cliff-shape.test.cjs
$env:SUITE='compare' # flow / random / sample2 も個別に実行
$env:BASE_REF='bdd98c7' # 比較元。省略時は修正版だけを実行
node tests/preparation-browser.cjs
```

検査は一時ブラウザと127.0.0.1のサーバーを使って終了時に閉じます。既存タブや保存ファイルは操作しません。`REPORT_FILE` を指定するとJSON結果、`CAPTURE_DIR` を指定すると比較画像を保存できます。

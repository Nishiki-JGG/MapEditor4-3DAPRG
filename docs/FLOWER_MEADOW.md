# 配置で配色する花畑

[色別一覧と配置例](../tests/flower_meadow_view.html) で、5色・同色・混色・色の帯を確認できる。風は初回表示から動き、接触テストも切り替えられる。本体の専用UIは追加せず、既存の配置・回転・拡縮を使う。

| ID | 表示名 | 三角形 | 高さ m | 材質 | 画像増分 |
|---|---|---:|---:|---:|---:|
| meadowwhite | 花畑・白 | 463 | .466 | 1 | 0 |
| meadowyellow | 花畑・黄 | 523 | .447 | 1 | 0 |
| meadowpink | 花畑・桃 | 433 | .477 | 1 | 0 |
| meadowred | 花畑・赤 | 463 | .461 | 1 | 0 |
| meadowviolet | 花畑・青紫 | 433 | .474 | 1 | 0 |

各パーツは同系色の10輪。色ごとに株元、花の向き、高さ、花弁数・大きさが異なる。5色合計2,315三角形。既存79 IDと並び順を保ち、カタログ84種、共有モデル25→30種。以前の25モデルと5画像は変更していない。既存512×512の共通アトラス（PNG258,248バイト）の白・葉・茎の領域を共用し、色は頂点色で付ける。外部画像・素材・新規サービスは使用していない。

## 配置の使い方

1. 本体の配置一覧で「花畑・白」など使いたい色を選び、配置する。同色だけを使えば統一した花畑になる。
2. 標準倍率で約.85〜1.05 m間隔を出発点に、向きと倍率を少し変えてつなぐ。密にしたい部分は近づけ、縁は株数を減らす。均一な正方形の土台はなく、不規則な株の輪郭が重なる。
3. 違う色を別々に置けば混色に、色ごとの列・領域を作れば帯状の植栽になる。各パーツ内で自動的に全色が混ざる構成ではない。色別のパーツを複数選択した場合は既存の配置ツールの選択方式に従う。
4. [白の花畑JSON](../samples/flower_meadow_white.json) と [混色の花畑JSON](../samples/flower_meadow_mixed.json) は既存のJSON読込で開ける。各54配置、計540輪。JSON読込は作業中のマップを置き換えるため、必要なマップを先に保存する。

花は横幅約1.1〜1.3 m、高さ約.45 mの低い群生。花弁と葉を形状で切り、真上から花面が見える。透明板を交差させず、アルファ重ね描きや透明部分の深度・影の問題を増やさない。斜めからは茎と葉、浅い花弁の曲面が見える。極端な横視点・接写に向けた厚い花弁や細密な萼は作っていない。

## 風・歩行接触・共有表現

既存のGPU風と接触ばねを利用し、別の更新システムは追加していない。根元の頂点は固定。花頭は輪ごとにまとまった重みを持ち、茎の下から上へ変位を増やす。個体位置と色別の位相で完全同期を避ける。風最大.13 m、接触最大.075 m、合成変位上限.15 mを標準倍率の出発点とし、倍率と頂点重みに応じて制限する。垂直方向・保存座標・基準頂点は書き換えない。

本体の無風・そよ風・強風を共通の設定から受け、環境効果量.7で風強度0 / .245 / .7になる。連続接触も上限内に収まり、離脱後6秒の検査で静止へ復帰した。風と接触が両方0なら基準形状と一致する。完全な長さ保存の物理計算ではないため、最大入力では少量の伸縮が残り得る。

Unityは同じライブラリ `shared-plants/5` と既存Runtimeを使う。今回のEditor取込コードも更新する。旧ライブラリ2・3・4の取込互換を確認した。接触には既存の `SharedPlantContactSource` と `SharedPlantContact.source` の割当が必要。配置後に接触対象を追加した場合は `Refresh()` を呼ぶ。元のゲーム本体へは組み込んでいない。

## 実際の検証

- ユーザーPCのChrome・SwiftShaderで93項目：旧79 ID・25共有モデル・5画像の保全、84 IDの一意性、分類・選択・配置・削除・回転・全体／縦倍率・保存再読込・共有モデル書出し・CSV丸め誤差。
- 18種の共有可動植物の実WebGL2頂点読戻し：無風の基準一致、根元固定、位相差、回転・非均等拡縮、風と接触の合成。複数の突風位相で新5色を含む変位上限の作動を確認。
- 全5色を本体の歩くモードで左右から通過。20秒連続接触、離脱復帰、影用材質、カリング、保存後の頂点・行列不変を確認。
- 真上90度の本体カメラ、通常距離17 m、近距離12 m、遠距離30 m、1.8 m人型で白・混色・帯状の各54配置を撮影。無風・そよ風・強風を同じ配置・カメラの時系列画像で比較。混色例の斜めの色反復を目視で見つけ、決定的な非周期の色選択へ調整した。
- 一覧の初回アニメーション、同色・混色・帯状、単体の近景と斜め、全5色の接触と復帰を確認。
- 隔離Unity6000.5.9f1 / URP17.5で109項目：30モデル・7配置、18種のブラウザGPUとの照合、7接触登録の通過・連続接触・復帰、旧2/3/4ライブラリ取込、ForwardとShadowのコンパイル。全5色を実URPで描画し時系列画像を保存。

## 負荷と制限

追加のCPU全頂点更新なし。新5色のGPU重みは55,560バイト。既存の最大8,000配置／種の事前確保設計では、5色の行列・色・ghost・接触CPU配列で合計3,617,280バイト増える。形状・JSON・GPUバッファは別。画像データは0増分。共有メッシュJSは非圧縮で1,587,350バイト増える（ローカルgzipでの差は約207 KiB、実際の配信方式は別）。同色の花畑は1種類のInstancedMesh、全5色を使う場合は最大5種類に分かれ、影の描画も必要になる。

接触CPUだけの4,000パーツ検査では候補100・有効2、95%点約.1 ms（PCのタイマー分解能を含む）。これは全体FPS・GPU負荷・スマホ性能の測定ではない。スマホ実機、長時間の発熱、Android/iOS、ゲーム本体統合、Unity Built-inは未検証。密度を上げると三角形数と影の負荷は配置数に比例する。急斜面ではモデル全体が地形に沿わず浮き・埋まり得るため、花畑は平坦〜緩斜面を基本にする。

生成は `node tools/plants/bake_meadow.cjs`。他の植物も再生成する場合は new → grass → understory → meadow の順。対応する検査は `meadow_source.py`、`meadow_validation.cjs`、`meadow_gpu.cjs`、`meadow_motion.cjs`、`meadow_visual.cjs`、`meadow_fields.cjs`、Unity `MeadowChecks.Run`。比較画像と個別PCのログ・プロジェクトはリポジトリ外へ保存する。

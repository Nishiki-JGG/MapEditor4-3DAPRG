# 岩とシダの共有化（ローカル検証版）

対象は既存の `rock` と `fern` だけ。基点は `c9128cf7f49c877a1aefc5fc4cf0f55f624fdfc4`。軽量なマップエディターの形を正本として固定し、Unity用の高ポリゴンモデルへ置き換えていません。水・他の小物・洞窟完成資産は対象外です。

## 正本と形式

`props/shared/assets.js` の `window.TDSharedData` が正本です。形（位置・法線・線形RGB頂点色・UV・三角形番号）とPNG、材質値を含む、JSONで表せるデータです。ブラウザは同期scriptで読み、同じオブジェクトを `shared_props.json` として書き出します。これにより既存の `file://` 起動を保ち、読み込み待ちの形や代替形を作りません。

現行repoには小物のUnityインポーターがなく、既存の出力は `props.csv` と `asset_catalog.json` によるPrefabの対応付けでした。ゲーム側 `game/client/Assets` のC#でも `props.csv` / `asset_catalog` / `yawOffsetDeg` を使う取り込みは確認できませんでした。GLBの新規依存を足さず、既存の水と同じく `JsonUtility` で読める小さな専用アダプターを追加しています。ゲームのPrefab解決処理そのものへの統合はこの検証に含みません。

| 項目 | 契約 |
|---|---|
| 種類ID・資産キー | `rock` / `tdj/rock`、`fern` / `tdj/fern`。既存値を維持 |
| 版 | `schemaVersion: 1`、`libraryVersion: shared-rock-fern/4`、岩 `version: 4`、シダ `version: 3`。内容を更新するときは資産版とライブラリ版を更新 |
| 単位・軸 | 1単位=1m、Unityローカル座標の +X右、+Y上、+Z前。Unityの正面は時計回り |
| ブラウザ変換 | 位置と法線のZを1回反転し、各三角形の第2・第3頂点を交換。正面を維持する。正本はUnityで外向きになる順序 |
| ピボット・接地 | `(0,0,0)`。最下頂点のY=0。元の形を接地用にY方向へ平行移動。岩全体 +0.193709448m後、小塊2つを −0.010916591m／−0.065251932m。シダ −0.029999999m。各塊の形・三角形数は維持 |
| 配置 | 既存CSVの位置、回転 `rotY_deg + catalog.yawOffsetDeg`、拡縮 `(scale,scaleY,scale)`。`scaleY` は絶対倍率。ブラウザでは回転の符号を反転 |
| 接地高 | 通常は地形の高さ、明示配置高があればその値。共有2種はブラウザだけの埋め込みオフセットを使わない |
| UV・画像 | UV原点は左下。PNGは上からの行順。ブラウザTextureLoaderはflipY=true、Unityは通常のPNG読み込み |
| 材質 | 線形頂点色 × sRGB画像 × 線形baseColor。lighting=lambert（拡散照明のみ）、鏡面反射・金属度・粗さ・環境反射なし |
| 葉 | cutoff=.42、両面、深度書き込みあり、半透明合成なし。PNGのalphaを影にも適用 |
| 画像取り込み | 非圧縮RGBA8、bilinear、ミップなし。岩repeat、シダclamp。両環境で同じPNGバイト列 |
| 可変表現 | この2種は静的。風変形、ランダム色、バイオームの苔・雪・濡れによる変調を外し、共有材質をそのまま使う。他の種類は従来どおり |

PNGは現行エディターの岩肌模様とシダのアトラス領域から固定しました。シダは元の1024²アトラスを丸ごと持ち込まず、必要な512×128領域だけを切り出し、UVを変換しています。岩は元の形と法線・頂点色を維持し、局所平面UVで同じ岩肌PNGを参照します。元の世界座標3面投影・動的な苔とは表示が異なります。

## 軽さの予算

| 種類 | 元→共有の三角形 | 頂点数 | 材質数 | 画像 | RGBA8画像メモリ（ミップなし） |
|---|---:|---:|---:|---|---:|
| 岩 | 120 → 120 | 360 | 1 | 256×256 | 256 KiB |
| シダ | 220 → 220 | 660 | 1 | 512×128 | 256 KiB |

増加は0三角形。画像のGPU用画素予算は合計512 KiBです。画像・材質は種類内の全配置で共有されます。これはGPU画像の概算で、JSON/base64文字列、展開中の画像、CPUコピー、エンジンの管理領域は含みません。ミップなしには遠景のちらつきという制約があります。

シダは既存の11枚の曲がった葉（各20三角形）のままです。抜かれた画素にもシェーダー計算の費用は残り、葉が重なる領域では複数回描かれ得ます。重なりのソフトウェア計測結果は検証証拠の `overlap.json` に残します。深度検査前の推定であり、GPU計測ではありません。スマートフォン実機の描画時間、熱、電池消費は **NotRun** です。三角形数を維持したことを、実機で高速になったという結果に読み替えません。

## 互換性とUnityでの使い方

- 保存データのschema・`propTypes`・種類順・配置配列は維持。旧マップをそのまま読み込めます。
- 既存CSVの列、既存カタログの値は維持。標準キーの2種にだけ任意の `sharedModel` 参照を追加し、ZIPに `shared_props.json` を1つ追加します。旧インポーターは従来ファイルを使用できます。
- `assetKey` を独自Prefabへ変更した種類は `sharedModel` を付けず、この取り込みではスキップします。その他の小物もスキップし、個数を返します。
- `unity/Assets/MapSharedProps` をUnityプロジェクトの `Assets/MapSharedProps` にコピーします。既存のMapWaterには触れません。Built-inおよびURP用のshaderを含みます。
- ZIPを展開し、`Tools > Map Editor > Import shared rock and fern (pilot)` からフォルダーを選びます。コードからは `MapSharedProps.EditorTools.MapSharedPropsBuilder.Build(folder)`。親Transformは任意です。
- 毎回、新しい `Assets/MapSharedPropsGenerated/Pilot...` にメッシュ・PNG・材質・Prefabを作り、CSV位置に配置します。既存Prefabを上書きしません。メニュー操作のシーン配置はUndo可能。生成資産を消すときは、その出力フォルダーを明示して削除してください。
- これは見た目の取り込みです。ゲーム固有の当たり判定・移動・カリング・LOD・Addressablesへの接続は追加していません。元のカタログのradius・heightは変更していません。

## 検証の再実行

```text
node tests/shared_props_validation.js <証拠フォルダー> <基点c9128cfのcheckout>
```

既存の使い捨てCDPブラウザで、旧マップ読み込み、既存書き出しの比較、実際のインスタンス行列、画像・材質、前後の描画を確認します。`tests/shared_props_view.html` は共有データを読む比較用の場面です。

Unityの試験は、別の検証専用プロジェクトに `MapSharedProps` と `tests/unity/` の検証用C#・無照明shaderをコピーし、URP 17.5.0を使います。ブラウザが生成した配置頂点の期待値とUnity実メッシュを比較し、前後をBuilt-inとURPで撮影します。起動はPCの `unity_once.py` を通し、他プロジェクトを開いたり変更したりしません。スマートフォンのPlayerビルドは行いません。

照明・環境反射・トーンマッピングはエンジンにより異なるので、同じ拡散照明モデルでも環境光や追加ライトの設定により画素の色は完全一致しません。URP版は主方向光と環境光を対象にした頂点照明です。形、左右の向き、接地、葉の抜き、PNGと材質値の一致をそれぞれ確認し、未実行の環境を区別します。

共有化にPBRは必要ありません。軽さを優先し、現版は両種類ともブラウザのMeshLambertMaterialとUnityの拡散照明shaderを使います。形・画像・UV・IDはそのままで、材質・正面順序・接地補正をライブラリ版4と各資産版で区別しました。無照明・非対称画像・実際のY=0接地面・FOV38度の7m/17m診断を別々に保存します。

# Obsidian reflection and optional native import

The existing black 40-triangle mesh had a low-roughness Standard material but neither a material environment map nor scene environment in the Web editor. The new adapter applies only to obsidian. It borrows the already allocated shared presentation environment, preferring an explicit scene environment. It does not allocate another cubemap, change any light or exposure, recolour the mesh, add emission, or modify other materials. Ambient intensity scales the borrowed reflection down in darkness. If no environment is available the original material remains usable without environment reflection.

The original positions, normals, vertex colours, geometry indices, dimensions, placement ID, radius and Web collider buckets are unchanged. No normal/roughness texture experiment from batch 113 is included. The original stylized pointed silhouette remains; this is a bounded visibility/reflection improvement, not realistic conchoidal rock modelling.

## Unity contract

The previous 43-asset small-prop reader did not import obsidian. New exports add an optional `obsidianV1` field to `small_props.json`, or its existing shared library, and the obsidian instance tint/root-position records. Core asset arrays are unchanged. The optional descriptor is version 1, restricted to canonical obsidian and 40 independent triangles. Missing, unknown-version, oversized or non-finite descriptor data is ignored with a warning rather than stopping the 43 existing prefabs. An old reader ignores the field and retains its prior omission of obsidian.

The new builder creates a standard Universal Render Pipeline/Lit material with the existing gloss values (metallic 0.1, smoothness 0.9), no emission or lights, and BlendProbes reflection reception. Standard Lit does not consume vertex colours, so the existing linear colours are rasterized into a shared padded 128-square colour atlas. This is a colour-format adapter, not a new artistic texture. No colour is intentionally brightened. Positions, normals and colours remain in the mesh; only display UVs are assigned for the atlas. The MeshCollider uses the exact exported 40-triangle geometry independently of those display UVs. Instances share mesh, atlas and material, with per-instance tint and explicit exported root position.

Provide an appropriate Reflection Probe or scene reflection environment in the destination Unity scene. The importer does not create a bright probe, change RenderSettings, or save modifications to a game scene. Without reflected illumination black glass naturally remains dark. Web uses the existing stylized presentation environment; Unity uses the receiving scene's environment, so pixel-identical appearance is not promised.

It creates the formal 44 prefabs, checks unchanged geometry/real colliders for all prior assets, validates the original obsidian geometry and 225 shared references, and actually generates the 43 prefabs for four missing/invalid cases. It also tests the existing shared-library route. The previous reader/build source is compiled with shared DTO aliases to retain compatibility with dependent chest builders; its previous control flow ignores the optional field and creates 43 prefabs. This is a source-logic compatibility check, not an old executable run.

The first validation stopped after successful 44-prefab import because its test incorrectly required colliders on deliberately non-colliding props. The check now requires equal actual collider counts, validates zero-collider metadata, and compares nonempty geometry/settings when present. The completed valid import was reused; missing/invalid/legacy cases were then generated and passed. No product failure was hidden.

`Glass114Review.Compare` captures the actual generated Prefab with reflection reception off/on under the same camera and lights. Near, opposite-light and the existing isolated production grassland generator (seed 71421) were reviewed. Facet separation improves without emission; the normal-distance difference is modest but observable. Original game scenes are not saved. Images and large export/build evidence remain local.

Web texture count remains 31 and draw calls remain 4 in both 9/225 cases. There are two additional compiled Web variants for the dedicated reflection/fallback material, not new geometry or textures. Unity adds one shared 128-square colour atlas (about 85.3 KiB uncompressed with mips), since this is a newly supported native asset. The final short GPU timing samples were taken after the dedicated Editor exited; their variation is not a general performance improvement claim. Player, mobile and complete gameplay sessions remain untested.


## Catalog metadata correction (115)

The first optional validator incorrectly required the default radius 0.4 and height 1.58. Normal catalog overrides, including `solid:false` (exported as radius 0), therefore omitted obsidian entirely. The validator now follows the existing core contract: finite radius >= 0 and finite height > 0. Canonical identity, fixed 40-triangle mesh bounds, normals/colours, index checks and non-emission checks remain unchanged. Positive radius retains the original shape MeshCollider; zero radius keeps the visible prefab and placed instance but creates no Collider. Radius/height metadata do not rescale this shape-based visual mesh or its shape collider.

`tests/obsidian-catalog.cjs` exercises real catalog application, save/reload, optional descriptor and full export. With the existing 114 evidence project, run it with OBSIDIAN_REVIEW_PROJECT set, then `python tests/prepare-obsidian-catalog.py` and `Glass115Checks.Run` in background Editor. The prior validator is compiled as a local test helper to reproduce rejection of three valid overrides. Ten actual imports verify default/custom/zero/non-solid (44 prefabs, one visible placement) and missing/unknown-version/nonfinite/oversized/negative-radius/zero-height (43 prefabs, no obsidian). Every case checks all prior 43 meshes and actual Collider content/counts. The atlas is the same cached asset and default geometry, normals, colours, material parameters and reflection implementation are unchanged. One disposable input file is reused rather than retaining ten large export copies.

The initial Web harness attempted to access the app before boot; adding the same explicit boot wait used by the existing tests resolved the harness error. The first Editor harness reserialized the whole DTO through JsonUtility, which changed absent core arrays into empty arrays and failed the existing circle-proxy validation before importing any prefab. The harness now replaces only the optional JSON object while preserving every byte outside it. Neither harness error required a product change. Old-reader compatibility remains a prior-source control-flow test, not an old binary execution. Player and GUI interaction were not used.

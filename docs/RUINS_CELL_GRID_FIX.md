# 壁のセル配置修正

## 原因と修正

表示格子は 0.5m のセル境界なのに、配置は壁の端面中心を格子交点へ吸着していた。このため厚さ 0.5m の壁が格子線をまたいでいた。直角接合時の補正だけでは根本原因を解消できなかった。

壁の両端と厚さから求めた基準矩形の四隅を格子境界へ合わせる。長さが 0.5m の奇数倍でも、回転が 0/90/180/270 度でも同じ占有ルールになる。瓦礫や装飾の張り出しは配置基準に含めない。表示側も TDRuins.GRID を参照し、配置側と同じ 0.5m 定数を使う。

接合後にも同じセル境界条件を検査し、直角接合や延長によって半マス位相に戻らないようにした。既存保存データ、ピボット、メッシュ、衝突形状、Unity 出力形式は変更していない。

## 互換性と対象

- 新規の直線壁同士はグリッド ON のまま直角接合・延長できる。
- 旧データの中心線配置や従来の専用角/T字部品に合わせると壁がセルからずれる場合、グリッド ON では接合吸着しない。グリッド OFF では従来の接合を使える。既存物を自動移動しない。
- 専用角/T字部品の寸法規格そのものは今回変更していない。
- グリッド幅は現行仕様の 0.5m 固定。幅を変更する UI はない。

## 検証

- ruins-cell-grid.cjs: 928 ケース。12種類、全4方向、負座標、端数座標、全壁長 0.5～32m、接合 ON/OFF、グリッド OFF、旧データ保持、反復回転。別途48ケースの格子上延長。
- ruins-corner-snap.cjs: 96 ケース。4方向、両端、壁長 1.5/2/4m、直角、延長、高さ不一致。
- ruins-cell-grid-browser.cjs: ローカルの実アプリをマウス操作し、横壁・縦壁・直角・延長・奇数長を5回配置。毎回プレビュー外周を検査し、確定後の個数と Undo/Redo を確認。
- 真上の正射影画像 top.png と斜め画像 oblique.png を validation/ruins-cell-grid/ に保存。正射影は検証時だけのカメラで、アプリ本体のカメラを変更しない。
- 旧中心線配置の接合テストはグリッド OFF の互換テストとして維持し、新セル配置の接合テストを別途追加。

全22本の遺跡関連 Node テスト、実ブラウザテスト、app.js / ruins.js の構文検査を通過。

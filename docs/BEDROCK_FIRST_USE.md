# 岩盤床：初回停止の修正と灰色の岩盤への再調整

この文書が最新のローカル検証記録。基準は並行更新を含む main `9d25b6f`。品質改善は未公開であり、既に公開・検証した `5e7b486` と区別する。

## 初回待ちの原因と修正

新規Chromeプロファイル、Chromeのシェーダーディスクキャッシュを無効にした同一48m平地で比較した。ドライバー内部のキャッシュまでは制御していない。

| 処理 | 基準main | 改善版 |
| --- | ---: | ---: |
| 最初の塗装のCPU更新 | 6.5ms | 7.4ms |
| 最初の通常描画 | 3,115.7ms | 13.4ms（準備中の既存シェーダー） |
| 岩盤の非同期準備 | 実描画が同期的に待つ | 約2.65秒、入力用タイマー最大間隔17.6ms |
| 準備後、実際に岩盤を描画 | 次の描画3.7ms | 5.4ms |
| 温間の塗装CPU／描画 | 6.3／12.1ms | 4.5／11.0ms |
| 温間の全体塗りCPU／描画 | 6.2／9.1ms | 5.9／8.3ms |
| 温間のJSON読込／読込後描画 | 56.9／3.6ms | 47.2／4.1ms |

基準版の3.12秒のうち約3.10秒が `getProgramInfoLog` で待っていた。描画後の `gl.finish()` は0msだったため、単に測定用のGPU待ちを長いUI停止と取り違えたものではない。画像は操作前に読込完了しており、画像要求から完了イベントまでは約366〜370ms、独立したGPU転送は約2.7msだった。画像の純粋なデコード時間とイベント待ちは分離していない。主因は初回プログラム準備である。記録は [latency-final.json](bedrock/latency-final.json)。

岩盤を選択・全体塗り・岩盤を含む保存データ読込のいずれかで、初回だけ `compileAsync` を開始する。画面に追加しない準備用の材質2個で、実シーンの照明・霧を使ってプログラムを準備する。既存の `STANDARD` 定義を保持し、準備用と本番の定義・キャッシュキーを一致させた。準備後に再コンパイルしてしまう試作の問題も修正した。シェーダーのエラーチェックは無効にしていない。

準備中も塗装・取り消し・保存のデータ更新を受け付ける。岩盤画像の表示は準備完了後になるため、最初の見た目の反映まで約3秒かかること自体は残る。その間は既存の床シェーダーで表示し、準備中で操作を保持する旨を通知する。保存データや地形・配置を準備のために書き換えない。岩盤を使わない初期サンプルでは専用準備もGPU画像転送も開始しない。毎フレームの新しい準備処理や描画パスはない。

## 実UIでの冷間操作

通常の描画ループを動かしたまま、実マウス、ボタン、ショートカット、ファイル選択で検証した。

- 準備中の145頂点分のストロークは、準備前後で塗装ハッシュが完全一致した。最終測定の最大入力タイマー間隔40.1ms、描画ループ間隔18.6ms。準備時間は約2.94秒。
- 準備中のUndo後に草ツールへ切り替えても、完了後に岩盤が勝手に復活しない。岩盤ツールの再選択だけでも床は変わらない。
- 全体塗りのUndo／Redoと準備中のJSON保存が塗装を保持した。全体塗りの準備は約2.98秒、最大入力間隔36.5ms。
- 新しいブラウザーで保存JSONを実ファイル入力から読んだ。準備全体は約2.93秒、最大入力間隔24.5ms。TABの要求も受け付けた。
- 読込中止ボタンで元のマップへ戻し、背景の準備完了後も元の塗装ハッシュと材質を保持した。
- 準備中の岩盤全体塗りを草へ変更しても、後から岩盤が適用されない。温間で草・岩盤・氷・土を連続切替してもプログラム数は増えない。

`tests/bedrock-first-use.cjs` と [first-use-ui.json](bedrock/first-use-ui.json) が証拠。準備をUndoしても一度開始したドライバーの処理はキャッシュとして完了させる。塗装やマップの取消は直ちにデータへ反映する。

## 未解決のプラットフォーム制約

**並列コンパイル拡張を使えない経路の秒単位の初回停止は、まだ解消していない。** デスクトップChrome上で `KHR_parallel_shader_compile` を返さないようにした模擬検証では、最初の実描画が約2.79秒、そのうち `getProgramInfoLog` が約2.78秒待った。温間描画は約12ms、温間JSON読込は約61ms。記録は [latency-no-parallel.json](bedrock/latency-no-parallel.json)。

WebGL 2のフェンスを使う試作も行ったが、`useProgram` が約3秒停止し、待ちを移しただけだったため不採用にした。[試作の記録](bedrock/latency-fence-rejected.json) は残すが、そのコードは製品に含めない。拡張ありの経路の結果を全ブラウザーへ一般化しない。iPhone／Androidの実機、WebGL 1、実際にこの拡張を提供しないGPUは未検証で、モバイル全般の初回応答を保証する状態ではない。

## 見た目の再調整

前回版は細粒と茶色が強く、大きな岩の構造が読み取りにくかった。参照2枚を再び実見し、参照の画素を入力・転用せず、灰色の広い面・連結した細い亀裂・控えめな白い鉱物脈を持つ別の独自画像を内蔵imagegenで生成した。プロンプトは [bedrock-prompt-v3.txt](../tools/bedrock-prompt-v3.txt)。生成元1254×1254のPNGは作業フォルダー直下の `generated-bedrock-meso.png` に保持している。

`tools/pack-bedrock.py` で512×512のRGBと浅い凹凸用Aへ梱包した。四つの内側パッチの混合を調整して大きな面と亀裂を残し、床だけの鉱物色を中立〜少し冷たい灰色へ調整した。単に全体をぼかしたり、土色にして岩へ合わせたりする方式ではない。ワールド座標に固定した模様で、追加の時変ノイズはない。

[6視点の比較画像](bedrock/quality-comparison.jpg) は、公開検証版 `5e7b486`、前回の未公開版 `0602072`、今回の改善の3列。真上・近距離・48m広域・斜め・緩斜面・土と草との境界を同じ地形・岩配置・照明・カメラで描画した。通常距離でも広い灰色の岩面と割れ目が読め、旧版の密な粒状面を減らせた。角張った既存の岩に対して細部の大きさも近づいた。

既存岩の上面は暖色寄りなので、近距離での色相差はまだ見える。床は連続した岩盤、パーツは大きな割れ岩という造形差もある。既存岩の形状・材質・自動配置は変更していない。完全な作風一致や反復の消滅は主張しない。テスト通過を美術品質の承認とも扱わない。

## 予算・サンプル保全

画像1枚、512×512、RGBA8＋全ミップ1,398,100バイト（約1.33MiB）。PNGは583,630バイト、埋込みJSは778,293バイト。RGBと浅い凹凸を同じ画像で参照し、画像参照は4回のまま。追加の頂点・三角形・描画回数は0。準備用オブジェクトは描画せず、実際の材質と同じプログラムキャッシュを利用する。

最新mainとの同一比較シーンは両方とも描画11回、三角形94,693、GPU画像19枚だった。25回の準備後描画の中央値はmain1.9ms、改善版1.8ms。計測した順序・PCでの参考値で、高速化や実機フレームレートの保証ではない。[比較記録](bedrock/quality-comparison.json) の `firstDrawMs` は、改善版では準備完了を待った後の描画7.6msであり、約3秒の非同期準備時間を含まない。元の固定8点での3×3画素平均の変動は最大7.34/255で、亀裂のコントラストが増えたため旧版の6.0より大きい点もある。これだけでちらつき改善を主張しない。

最新main `9d25b6f` の完成済みサンプルを元に、`tools/repack-bedrock-samples.cjs 9d25b6f` で照合キーを再梱包した。地形・配置・衝突・歩行情報はデコード後の完全一致で検証し、岩の形状は再生成していない。途中で読込版番号が変わって森のキーだけが古く残った問題を検出し、梱包中のソース変更を検出して書込みを止めるガードを追加した。最終の梱包・照合・実UI検証はソースを固定して実行する。

最終の実UI検証は、森・遺跡とも初回バンドル、再読込キャッシュ、TAB往復を含め再生成0回。キー・プロファイルが一致し、マップ・形状・配置のハッシュもmainと一致した。未使用の岩盤シェーダーは非有効、GPU画像も未転送。[サンプル比較](bedrock/prepared-comparison-quality.json) と [キー照合](bedrock/prepared-key-audit.json) に保存した。

塗装・全体塗り・Undo／Redo・JSON復元・歩行、マウス／タッチ、材質切替後の画像ハッシュ一致、資産レジストリ保存、部屋ZIPのブラウザーテストが通過した。トンネル、資産レジストリ、共通資産保存、部屋セット、表面塗装の単体検証と準備済みデータの整合性チェックも通過した。既存の草・土・荒地は通知を除く920×680pxでRGB差分0を確認した。[既存床の比較記録](bedrock/existing-pixels-final.json)。

mainのトンネル、資産レジストリ、部屋保存の更新を保持した。Unityプロジェクト、既存の岩・壁、草・土、海・波、泉には今回の変更を加えていない。初回停止以外の既知の海HLSL同期テストのCRLF差異は、以前の [証拠](bedrock/sea-line-endings.json) を参照。

# マップエディター 修正報告（Revision 19）Unity でも同じ海

Revision 18 の海（寄せる波・砕け波・打ち上がり・泡・海底の光の網目・海草の斑点・きらめき・濡れた砂）を、Unity でも作れるようにしました。エディターと Unity で、同じ式と同じノイズを使います。

## 式は 1 か所だけ（`sea.js`）

- 海の式（波の高さ・色・泡・光の網目・濡れた砂）は `sea.js` に、GLSL と HLSL の両方が読める書き方で 1 度だけ書きました。
  - 型は `float2/3/4`、関数は `frac`・`lerp`・`atan2` と書きます。
  - コンストラクタには、要素をすべて書きます。HLSL には `float3(0.)` のような書き方がないためです。
  - 割った余りは `seaMod` で計算します。GLSL の `mod` と HLSL の `fmod` は、負の数で答えが違うためです。
  - 定数は `#define` で書きます。
- **エディター**：`sea.js` の先頭に GLSL 用の `#define`（`float2` → `vec2` など）を付けて、水のシェーダーに入れます。見た目は Revision 18 と同じです（並べた画像で確認）。
- **Unity**：`node tools/sea/build-sea-hlsl.cjs` で、同じコードから `unity/Assets/MapWater/Runtime/Shaders/MapSeaShared.hlsl` を作ります。
  - このファイルは手で直さないでください。`sea.js` を直して、作り直してください。
- **`tests/sea_hlsl_sync.cjs`**：次の場合に失敗します。
  - `MapSeaShared.hlsl` が `sea.js` と違う。
  - 共有のコードに、片方の言語でしか読めない書き方（`vec3(`・`fract`・`mix`・`mod`・`atan(`・引数 1 つのコンストラクタ・大域の `const` など）がある。
  - Unity の shader が、必要な大域を宣言・代入していない。

## 書き出し

海のある地図では、次を足しました。

- **`sea_field.png`**（地形と同じ解像度。画像の上の行が Unity の z の最大で、ほかの画像と同じ並び）
  - R,G：水際までの距離 s（m）。16 ビット、−20〜60m、刻みは約 1.2mm。
  - B：岸への向き（Unity の xz で、+x から +z へ回る角度。B/256 × 360°）
  - A：海の重み。地図の端につながる水は 1、その浜は内陸 4m ほどで 0 へ、囲まれた池・湖は 0。
- **`meta.json` の `sea`**
  - 波：波長 7.5m、周期 4.4 秒、高さ、急になり始める深さ、崩れる深さ、打ち上がりの高さと届く距離
  - 水の色：浅い・深い（エディターと同じ値のまま）
  - 太陽の向き（Unity の座標）
  - 画像の読み方
- `meta.json` の `water[0].waves` は、`meta.sea` と同じ波の数値です。
- 海のある地図では、これまでどおり池・川の流れの画像（`waterSim`）は出しません。

## Unity

- **`MapWater/Sea`**（`MapSea.shader`。URP、半透明）
  - Unity の座標を、エディターの座標（x = Unity x − 地図の半分、z = 地図の半分 − Unity z）に直して、`MapSeaShared.hlsl` の式を呼びます。
  - 頂点では、エディターと同じく水面を波の高さだけ上下させ、その傾きで波の面に陰影を付けます。
  - 最後に、エディターと同じく 2.2 乗して、ガンマから線形に直します。
- **`MapWaterBuilder.Build`**：書き出しに `meta.sea` があれば、`BuildSea` が海を作ります。
  - `sea_field.png` と `heightmap_r16.raw` から、約 0.5m 間隔（エディターと同じ）の格子のメッシュを作ります。
  - 作るのは、海の重みがある所と、水際から少し陸の所までです。
  - 頂点に入れるもの：uv0 = (水際までの距離, 海の重み)、uv1 = 岸への向き（エディター座標）、uv2.x = 静水の水深
  - 材質には、波の高さ・水の色・太陽の向き・地図の大きさを、`meta.sea` から入れます。
  - 水の色は `Vector` で渡します。色として渡すと Unity が値を変換してしまうためで、エディターと同じ値のまま渡しています。
  - できる物：`MapWater_<名前>/Sea`（`MeshRenderer`、影なし）。資産は `Assets/MapWaterGenerated/<名前>/` に、`Sea.mesh.asset` と `Sea.mat` が入ります。
  - 作れないとき（画像や heightmap が無い、大きさが違う、海の所が無い）は、「MapWater: 海は作りません — 理由」を返し、何も増やしません。
- 海の時間は Unity の `_Time.y` です。エディターとは開始の時刻が違うので、ある瞬間の波の位置は同じになりません。
- 波の高さは書き出したときの天候の風で決まります（風なし 0.38m、強風 0.77m）。材質の `_WaveHeight` で変えられます。

## 確認したこと・していないこと

- **確認した**
  - `tests/sea_waves.js`（9 項目）：書き出した `sea_field.png` と `heightmap_r16.raw` を、`BuildSea`（C#）と同じ読み方で読んだ値が、エディターの値と一致する。
    - 距離の差は 0.5mm 以内、海の重みの差は 0.002 以内、水深は一致、向きの内積は 0.9999
    - 行の並び・16 ビットの距離・角度の向き・z の反転を、まとめて確かめています。
  - `tests/sea_hlsl_sync.cjs`（13 項目）：上の「式は 1 か所だけ」の検査
  - エディターの海の見た目が、共通化の前後で変わらない。
- **確認していない**
  - この作業の環境には Unity も、C#・HLSL のコンパイラもありません。そのため、`MapSea.shader`・`MapSeaShared.hlsl`・`MapWaterBuilder.BuildSea` は、Unity で一度もコンパイル・実行していません。
  - 書き方は、既存の `MapWater.shader`・`MapWaterBuilder.cs` に合わせ、HLSL で読めない書き方はテストで弾いています。
  - それでも、Unity で最初に開いたときに、コンパイルのエラーが出ないかを確かめてください。

- 全体の回帰テスト：実行中（結果はこの後に追記します）。

# ゲーム向けの素材台帳と保存・取り込み

2026-10-30：編集保存は圧縮した `.map`、Unity用ZIPはschema 5です。旧JSON/旧ZIPも開けます。

## 普段の操作
編集内容は「保存」または「名前を付けて保存」で残し、「開く」で編集を再開します。Unityへ渡すときは次の操作を行います。

1. エディタで「Unity用に書き出す」を押し、最初に書き出し先のフォルダを選ぶ。
2. 以後の同じ画面での書き出しは、そのフォルダへ出力する。書き出し先を変える場合はページを開き直して選び直す。
3. 新しい部屋・新しい素材でも同じボタンでよい。素材ZIPを追加で手動保存する必要はない。
4. 保管フォルダを指定してゲームへの取り込みを依頼する。部屋と `_shared` を一緒に保管する。

```text
Maps/
  _shared/
    objects/<素材の内容SHA>.json
    <共通版SHA>/shared_assets.json
    <共通版SHA>/*.recipe.json
  room-部屋名-内容ID/
    map.map
    map_export_unity.zip
    saved.txt
```

同じ素材は何部屋で使用しても保存は一つ。新規・変更素材だけを追加し、旧部屋が参照する版を上書きしない。部屋を編集した場合も内容ID別のフォルダに保存する。同じ内容の再保存では重複しない。どの旧版を削除してよいかの自動判定は今回行わない。

共通素材は、モデル1件・画像1件などの単位で分け、内容SHAをキーに保存する。共通版のレシピは構成と順番を保持し、元のJSONをbyte一致で復元する。名前や配列順だけを資産同一性の根拠にしない。

「詳細な書き出し」にある「編集データ＋Unityデータ（ZIP）」「共通素材（ZIP）」は個別のダウンロード・移送用として残す。部屋セットだけを別PCへ渡すと素材が不足するため、必要な共通ZIPまたは `_shared` も渡す。

フォルダへの直接保存にはPC版Chrome/Edgeなどの対応ブラウザが必要。ディレクトリ選択はユーザー操作から行い、許可した範囲にだけ保存する。[ブラウザAPIの条件](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)

## ゲームへの取り込み

```powershell
python tools/receive-room.py "C:/Maps/room-部屋名-内容ID" --output "C:/Import/RoomA"
```

受付は出力先にある素材台帳、明示した共通保管先、部屋と親フォルダの順に必要な版を探す。登録済み素材だけの新マップなら共通ZIPを再度持ち込む必要はない。未登録なら入力側台帳または従来の共通ZIPから追加する。欠損・改変・参照不一致はエラーで止め、別モデルで代用しない。

Unityの既存Builderはレシピを復元してモデル・画像を読み込み、Assets/MapSharedAssetCacheのMesh/Textureを再使用する。部屋ごとの配置・色・接地画像・Materialは混ぜない。Playerの実行時にZIP展開や素材ダウンロードは行わない。

新しいモデルはshared-registry/1の明示bindings（素材ID・assetKey・版）と構造検査で取り込む。素材名をC#の固定リストへ追加する必要はない。対応形式は現在の三角形メッシュ・PNG・Lambert材質・既存の風/接地仕様。新しいシェーダーや別形式まで自動変換する機能ではない。旧shared-plants等の形式も維持する。

部屋カタログの登録・Seed抽選は既存MapRoomCatalogBuilder/MapRoomSeedBuilderを使用する。試験では新規素材・変更素材を含むPrefabがカタログに登録され、Seed生成候補として参照できることまで確認する。

## 完了範囲と残作業
- 今回: 素材単位の自動保存・取り込み時の再利用、新素材ID対応、旧部屋の素材参照保持。
- 既存の一括Prefab取り込み未対応（水・橋・一部の加工形状など）は残る。部屋の地形・歩行・全景観の合格や、ユーザーの全マップの正式登録を意味しない。
- 完成前の部屋を自動で実カタログへ登録しない。受け取り時の出入口・検証エラーと、未対応形式の拒否は維持する。
